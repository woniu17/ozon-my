## 1. 背景与目标

### 1.1 现状问题

ERP 系统支持本地部署和远程部署两种形态：

| 部署形态 | 公网可达 | sharp 渲染 | 落盘能力 | 典型场景 |
|---|---|---|---|---|
| 本地 ERP | ❌ | ✅ | ✅ | 开发调试、日常运营 |
| 远程 ERP | ✅ | ✅ | ✅ | 正式上架、OPI 可拉图 |

**核心矛盾**：

- 本地 ERP 跑水印加工链时，`processImage` 会下载原图 → sharp 渲染 → 落盘到 `public/images/`，返回的 URL 形如 `http://localhost:3001/images/{sku}/{hash}.jpg`。
- Ozon OPI 服务器在公网，**无法访问本地 ERP 的 localhost 地址**，导致上架时图片 URL 不可达，商品图片审核失败。
- 远程 ERP 虽然有公网 URL（如 `https://2.tencent.yochylin.com:17443`），但本地 ERP 无法直接利用它的渲染能力。

### 1.2 设计目标

构建一个**图片处理代理**机制：

- 本地 ERP 在 `IMAGE_HOST_MODE=remote` 模式下，**不下载、不渲染、不落盘**，而是把图片处理请求转发给远程 ERP。
- 远程 ERP 完成下载、渲染、落盘后，返回**公网可访问的 URL**给本地 ERP。
- 本地 ERP 把该 URL 作为图片地址写入 OPI 上架请求，Ozon OPI 服务器能正常拉取。

### 1.3 设计原则

| 原则 | 说明 |
|---|---|
| 最小改动 | 复用远程 ERP 现有的 `processImage`，只新增一个薄接口 |
| 向后兼容 | 默认 `IMAGE_HOST_MODE=local`，不配置则行为不变 |
| 降级安全 | 远程调用失败时透传原图 URL，不阻断上架流程 |
| 幂等继承 | 远程 ERP 的 hash 落盘缓存对代理请求同样生效 |
| 鉴权独立 | 服务间调用用独立 token，不走 JWT 用户登录态 |

## 3. 配置设计

### 3.1 新增环境变量

| 变量名 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `IMAGE_HOST_MODE` | 否 | `local` | 图片处理模式：`local`=本地处理 / `remote`=远程代理 |
| `REMOTE_IMAGE_HOST_URL` | `remote` 模式必填 | 空 | 远程 ERP 地址（不带尾斜杠），如 `https://2.tencent.yochylin.com:17443` |
| `REMOTE_IMAGE_HOST_TOKEN` | `remote` 模式必填 | 空 | 服务间调用鉴权 token（32 字节随机字符串） |

### 3.2 配置加载（config/index.js）

```javascript
imageHostMode: process.env.IMAGE_HOST_MODE || 'local',
remoteImageHostUrl: (process.env.REMOTE_IMAGE_HOST_URL || '').replace(/\/$/, ''),
remoteImageHostToken: process.env.REMOTE_IMAGE_HOST_TOKEN || '',
```

### 3.3 配置示例

**本地 ERP `.env`**：
```bash
IMAGE_HOST_MODE=remote
REMOTE_IMAGE_HOST_URL=https://2.tencent.yochylin.com:17443
REMOTE_IMAGE_HOST_TOKEN=a1b2c3d4e5f6...（32字节随机字符串）
```

**远程 ERP `.env`**：
```bash
IMAGE_HOST_MODE=local
IMAGE_HOST_BASE_URL=https://2.tencent.yochylin.com:17443
REMOTE_IMAGE_HOST_TOKEN=a1b2c3d4e5f6...（与本地一致）
```

### 3.4 配置校验

启动时（`app.js`）增加配置校验：

| 条件 | 行为 |
|---|---|
| `IMAGE_HOST_MODE=remote` 且 `REMOTE_IMAGE_HOST_URL` 为空 | 启动失败，日志报错 |
| `IMAGE_HOST_MODE=remote` 且 `REMOTE_IMAGE_HOST_TOKEN` 为空 | 启动失败，日志报错 |
| `IMAGE_HOST_MODE=remote` 且 URL 非 https | 日志 warn（允许 http 但不推荐） |

## 4. 接口设计

### 4.1 远程图片处理接口（批量）

**接口名**：批量处理图片（远程模式专用）

| 项 | 内容 |
|---|---|
| 路径 | `POST /admin/api/image-host/process-batch` |
| 鉴权 | `x-image-host-token` header（独立 token，非 JWT） |
| Content-Type | application/json |
| 调用方 | 本地 ERP 的 `processImageBatchRemote` 函数 |
| 单次上限 | urls 数组 ≤ 20 张（防止单请求过大） |

**为什么用批量接口**：watermark.js 处理一个 SKU 时通常有 5-10 张图，单图接口下 N 张图 = N 次 HTTP 往返，远程模式累计开销大。批量接口下 N 张图 = 1 次 HTTP 往返，远程可 `Promise.all` 并行下载渲染，性能提升约 6-8 倍。

**请求体**：
```json
{
  "urls": [
    "https://ir-7.ozone.ru/.../1.jpg",
    "https://ir-7.ozone.ru/.../2.jpg",
    "https://ir-7.ozone.ru/.../3.jpg"
  ],
  "sku": "4143566763",
  "templateConfig": {
    "type": "border",
    "border": { "width": 10, "color": "#ffffff", "opacity": 0.5 }
  }
}
```

**响应体（成功）**：
```json
{
  "ok": true,
  "results": [
    { "originalUrl": "https://ir-7.ozone.ru/.../1.jpg", "publicUrl": "https://2.tencent.yochylin.com:17443/images/4143566763/a1b2.jpg", "ok": true, "cached": false },
    { "originalUrl": "https://ir-7.ozone.ru/.../2.jpg", "publicUrl": "https://2.tencent.yochylin.com:17443/images/4143566763/b2c3.jpg", "ok": true, "cached": true },
    { "originalUrl": "https://ir-7.ozone.ru/.../3.jpg", "publicUrl": null, "ok": false, "error": "下载原图失败: HTTP 404" }
  ]
}
```

**响应码**：
| HTTP Code | 含义 |
|---|---|
| 200 | 处理完成（含单图失败，看 results[].ok 字段） |
| 401 | token 鉴权失败 |
| 400 | 请求体非法（urls 非数组/为空/超 20 张） |
| 500 | 服务异常 |

**失败隔离**：单张图片处理失败不影响其他图片，失败项在 results 中返回 `ok:false + error`，调用方（watermark.js）对失败项透传原图 URL。

### 4.2 鉴权机制

| 项 | 说明 |
|---|---|
| 方式 | Header `x-image-host-token` |
| 校验 | 字符串等值比较 |
| 独立性 | 不走 `authMiddleware`（JWT 中间件），路由内单独校验 |
| 生成 | `openssl rand -hex 32` 或 `node -e "console.log(crypto.randomBytes(32).toString('hex'))"` |

### 4.3 接口时序图

```
本地 ERP                              远程 ERP
   │                                     │
   │  POST /image-host/process-batch     │
   │  {urls:[...], sku, templateConfig}  │
   │  x-image-host-token: xxx            │
   │ ───────────────────────────────────▶│
   │                                     │
   │                  ┌──────────────────┴──────────────────┐
   │                  │ token 鉴权                          │
   │                  │ 校验 urls 数组                      │
   │                  │ Promise.all(urls.map(processImage))│
   │                  │  ├─ 图1: 下载→渲染→落盘→publicUrl  │
   │                  │  ├─ 图2: 缓存命中→publicUrl         │
   │                  │  └─ 图3: 失败→ok:false              │
   │                  └──────────────────┬──────────────────┘
   │                                     │
   │  {ok:true, results:[                │
   │    {originalUrl, publicUrl, ok,     │
   │     cached, error?}...]}            │
   │ ◀───────────────────────────────────│
   │                                     │
   │  把 results 还原到 item.images:     │
   │  成功项替换为 publicUrl              │
   │  失败项透传原图 URL                  │
```

## 5. 模块设计

### 5.1 本地 image-host.js 改造

**核心**：新增 `processImageBatch(urls, sku, templateConfig)` 批量入口，根据 `config.imageHostMode` 分流。原 `processImage` 单图函数保留（供 `previewWatermark` 等单图场景使用）。

```
processImageBatch(urls, sku, templateConfig)
  │
  ├─ config.imageHostMode === 'remote'
  │     └─ return processImageBatchRemote(urls, sku, templateConfig)
  │
  └─ config.imageHostMode === 'local'（默认）
        └─ return processImageBatchLocal(urls, sku, templateConfig)
              └─ Promise.all(urls.map(url => processImageLocal(url, sku, templateConfig)))
                 失败项透传原图 URL，返回统一结构 { results }
```

**统一返回结构**（本地/远程一致）：
```typescript
{
  results: Array<{
    originalUrl: string,   // 原图 URL
    publicUrl: string|null,// 处理后公网 URL(失败为 null)
    ok: boolean,           // 是否成功
    cached: boolean,       // 是否命中缓存
    error?: string         // 失败原因
  }>
}
```

**processImageBatchRemote 流程**：

| 步骤 | 说明 |
|---|---|
| 1. 配置校验 | `REMOTE_IMAGE_HOST_URL` 和 `REMOTE_IMAGE_HOST_TOKEN` 必填 |
| 2. 构造请求 | `POST {remoteUrl}/admin/api/image-host/process-batch` |
| 3. 设置 header | `x-image-host-token` + `content-type: application/json` |
| 4. 设置超时 | `headersTimeout: 120s` / `bodyTimeout: 120s`（批量下载+渲染可能较慢） |
| 5. 解析响应 | `data.ok === true` 返回 `data.results`，否则整体抛错 |
| 6. 异常处理 | 网络错误/超时/非 200 整体抛错，由 watermark.js 捕获后所有图透传原图 |

**降级策略**：整体失败（网络/鉴权）时所有图透传原图；单图失败时仅该图透传原图。

### 5.2 远程接口实现（config.js）

**路由位置**：`src/modules/config.js`（与现有 `/admin/api/preview/watermark` 同文件）

**关键逻辑**：
1. 校验 `x-image-host-token`
2. 校验请求体 `urls`（数组、非空、≤ 20 张）/ `sku` / `templateConfig`
3. `Promise.all` 并行处理：每张图调 `processImage`，失败项捕获返回 `ok:false`
4. 返回 `{ok:true, results}`

```javascript
// 远程接口伪代码
router.post('/admin/api/image-host/process-batch', async (req, res) => {
  if (req.headers['x-image-host-token'] !== config.remoteImageHostToken) {
    return res.status(401).json({ ok: false, error: 'invalid token' });
  }
  const { urls, sku, templateConfig } = req.body;
  if (!Array.isArray(urls) || urls.length === 0 || urls.length > 20) {
    return res.status(400).json({ ok: false, error: 'urls 必须为非空数组且≤20张' });
  }
  const results = await Promise.all(
    urls.map(async (url) => {
      try {
        const publicUrl = await processImage(url, sku, templateConfig);
        return { originalUrl: url, publicUrl, ok: true, cached: /* existsSync 预判 */ };
      } catch (e) {
        return { originalUrl: url, publicUrl: null, ok: false, cached: false, error: e.message };
      }
    })
  );
  res.json({ ok: true, results });
});
```

### 5.3 watermark.js 改造

**改造前**（逐张串行）：
```javascript
for (const img of item.images) {
  if (!img?.file_name || !/^https?:\/\//i.test(img.file_name)) continue;
  const publicUrl = await processImage(img.file_name, sku, templateConfig);
  img.file_name = publicUrl;
}
```

**改造后**（一次批量）：
```javascript
const urls = item.images
  .map(im => im?.file_name)
  .filter(u => u && /^https?:\/\//i.test(u));
if (urls.length > 0) {
  const { results } = await processImageBatch(urls, sku, templateConfig);
  const urlMap = new Map();
  for (const r of results) {
    urlMap.set(r.originalUrl, r.ok ? r.publicUrl : r.originalUrl); // 失败透传原图
  }
  for (const img of item.images) {
    if (urlMap.has(img.file_name)) img.file_name = urlMap.get(img.file_name);
  }
}
```

**优势**：本地模式 `Promise.all` 并行渲染（原为串行）；远程模式 1 次 HTTP 代替 N 次。

### 5.4 降级策略

| 失败场景 | 降级行为 | 阻断上架 |
|---|---|---|
| 远程接口网络不通/超时 | processImageBatchRemote 抛错 → watermark.js 所有图透传原图 | 否 |
| 远程接口返回 ok:false（整体） | processImageBatchRemote 抛错 → 所有图透传原图 | 否 |
| 远程单图处理失败 | results 中该项 ok:false → 该图透传原图，其他图正常 | 否 |
| 远程 sharp 未安装 | 远程 results 中对应项 ok:false → 透传原图 | 否 |
| token 鉴权失败 | 远程返回 401 → 抛错 → 所有图透传原图 | 否 |
| 远程磁盘满 | 远程 processImage 抛错 → ok:false → 透传原图 | 否 |

**降级链路**：`processImageBatchRemote 抛错 → watermark.js apply 捕获 → img.file_name 保持原图 URL → prepareBundleItems 继续 → commitListing 提交原图 URL 给 OPI`

## 7. 安全设计

### 7.1 鉴权安全

| 项 | 措施 |
|---|---|
| token 强度 | 32 字节随机字符串（256 bit） |
| 传输加密 | 远程 ERP 必须 HTTPS |
| 接口隔离 | 独立于 JWT 中间件，路由内单独校验 |
| 存储安全 | token 存 `.env`，不入库不入日志 |
| 等值比较 | 使用 `crypto.timingSafeEqual` 防时序攻击（可选） |

### 7.2 接口安全

| 风险 | 措施 |
|---|---|
| 未授权调用 | token 鉴权 |
| 请求体过大 | 限制 `url` 长度 ≤ 2048，`sku` ≤ 64，`templateConfig` ≤ 8KB |
| URL 注入 | 校验 `url` 必须是 http/https 开头 |
| SSRF | 远程 ERP 的 processImage 已有原图 URL 下载，代理不引入新 SSRF 风险 |
| 滥用刷量 | 可选：每 token 每分钟限 100 次（本次不实现，后续按需加） |

### 7.3 数据安全

| 项 | 说明 |
|---|---|
| 图片缓存 | 远程 ERP 落盘的图片以 hash 命名，不含敏感信息 |
| 日志脱敏 | 日志不记录 token 原文，只记录前 4 位 + `***` |
| 请求记录 | 远程接口可记录调用日志（sku + cached + 耗时），便于审计 |

## 8. 性能设计

### 8.1 性能指标预估

| 场景 | 单图接口（已废弃） | 批量接口（采用） | 提升 |
|---|---|---|---|
| 10 张图（本地模式） | 串行 10 × 1s = 10s | Promise.all 并行 ≈ 1.5s | ~6 倍 |
| 10 张图（远程模式） | 10 次 HTTP × 2s = 20s | 1 次 HTTP + 远程并行 3s = 3s | ~6 倍 |
| 5 SKU 并发（各 8 张） | 40 次 HTTP | 5 次 HTTP（每 SKU 1 次） | ~8 倍 |
| 缓存全命中（10 张） | 10 × 0.1s = 1s | 1 次 HTTP + 远程 10 次 existsSync = 0.2s | ~5 倍 |
| 网络故障 | 不适用 | 120s 超时后降级 | 透传原图，不阻断 |

### 8.2 优化措施

| 措施 | 说明 |
|---|---|
| 幂等缓存 | 远程 hash 落盘缓存，重复请求直接返回 |
| 本地 URL 缓存（可选） | 本地可缓存 `url+templateConfig → publicUrl` 映射，避免重复请求远程（本次不实现） |
| 超时控制 | `headersTimeout: 60s` / `bodyTimeout: 60s` |
| 连接复用 | undici 自动复用 TCP 连接（keep-alive） |

### 8.3 与两阶段架构的配合

本方案与已完成的"图片处理/OPI 上架两阶段架构"**完全兼容**：

```
batch-image-poller（第一阶段，不限速）
  └─ prepareListing → processImage → 转发远程
       远程处理完返回公网 URL
       本地不阻塞于图片下载，第一阶段速度更快

batch-upload-poller（第二阶段，限速 intervalSec）
  └─ commitListing → opi.productImport
       提交的 images 已是远程公网 URL，Ozon 能拉到
```

### 9.1 部署步骤

**远程 ERP**：
1. 更新代码（含新增的 `/admin/api/image-host/process-batch` 批量接口）

1. 更新代码（含 image-host.js 改造）

4. `.env` 设置 `REMOTE_IMAGE_HOST_TOKEN=<与远程一致>`
5. 重启服务

| 代码回滚 | git revert，配置项有默认值 `local`，不影响原有功能 |

| 风险 | 等级 | 对策 |

| 并发压垮远程 | 低 | batch-image-poller 并发度仅 5，远程 processImage 幂等缓存命中率高 |
