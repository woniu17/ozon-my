# 上架素材机制（Listing Material System）设计方案

> 版本：v1.0（2026-10-24）
> 范围：`erp-backend-lite` 扩展设计
> 状态：待评审

---

## 1. 背景与目标

### 1.1 现状

当前 `erp-backend-lite` 已具备完整的「跟卖/批量上架」链路：

1. **源数据**：采集箱/缓存（`product_data_cache` + `product_attributes_cache`）或 Ozon API（`ozon-opi.js`）提供商品原始数据。
2. **组装**：`listing-builder.js#buildListingMessage(sku, storeId, options)` 从缓存合成完整 item，注入价格、强制字段（品牌/卖家代码/型号名称）、图片顺序策略。
3. **加工**：`prepare-bundle.js#prepareBundleItems` 执行图片加工链 `ai_rewrite → watermark → ai_poster → copy_ban`，输出 `transformedItems`。
4. **上架**：`commitListing` 调 `opi.productImport`（`/v3/product/import`），经 `import-status-poller` 跟踪任务状态。
5. **批量**：`batch_upload_tasks` 支持多店铺批量上架。

### 1.2 痛点

| 问题 | 说明 |
|---|---|
| 素材不可沉淀 | 每次上架是一次性任务（`follow_sell_task_payloads` 只存任务快照），优化过的标题/描述/图片/属性用完即弃，无法复用、比较、版本管理 |
| 差异化靠“随机” | 目前差异化 = 强制改品牌/型号名称/卖家代码 + 图片随机排序 + 可选水印，标题/描述/属性没有真正“重新优化”，同一商品在多店内容几乎相同，易触发 Ozon 同款合并/限流 |
| 无审核环节 | AI 重写/人工优化结果直接上架，不能先保存为素材再人工确认 |
| 无素材库 | 缺少一个“可上架内容包”的一等公民实体，无法支持后续的 A/B 效果分析 |

### 1.3 目标

引入 **素材层（Listing Material）**，把「商品内容」从「上架动作」中解耦：

- 同一商品可生成 **一份或多份** 独立素材（标题/描述/图片/属性/价格各不相同）。
- 素材可保存、可版本化、可审核、可复用。
- 素材可发布到 **另一家店铺**，并记录发布历史。
- 完全复用现有上架管线，不改动 `follow_sell` / `batch-upload` 的任务跟踪机制。

## 2. 核心概念

### 2.1 源商品（Source Product）

来自采集箱/缓存/已有店铺商品的完整数据，关键来源：

- `product_data_cache.data`：名称、图片、`description_category_id`、`type_id`、价格、库存等。
- `product_attributes_cache.attributes_data`：`/v4/product/info/attributes` 返回的属性值。
- `product_attributes_cache.description_data`：`/v1/product/info/description` 返回的描述（含富内容）。

### 2.2 上架素材（Listing Material）

一份独立的、可发布的商品内容包，字段对齐现有 `item` 结构（`transformItemForPortal` 的输入），包含：

- 基础信息：`name`（标题）、`description`（4191 纯文本）、`rich_content`（11254 富内容 JSON）、`description_category_id`、`type_id`。
- 图片集：`primary_image` + `images[]`（已加工 URL）。
- 属性集：`attributes[]`（v3 格式 `[{complex_id,id,values:[{value,dictionary_value_id}]}]`）。
- 价格策略：`price_config`（`salePrice/oldPrice/minPrice`，或引用 `listing_templates`）。
- 其他：`default_stock`、`video_url`、`offer_id` 规则。

### 2.3 素材版本（Material Version）

每次编辑保存产生一个版本，存完整快照，支持回溯。

### 2.4 素材变体 / 分组（Material Group）

同一源商品生成的 N 份素材属于同一个 `group_id`，每份素材是独立可上架单元，对应“一份或多份”。

## 3. 数据模型

### 3.1 新增表

```sql
-- ① 素材主表：一份可上架的完整商品内容包
CREATE TABLE IF NOT EXISTS listing_materials (
  id                      INTEGER PRIMARY KEY AUTOINCREMENT,
  material_no             TEXT UNIQUE NOT NULL,   -- 业务编号 mat-{timestamp}-{rand}
  group_id                TEXT NOT NULL,          -- 同源商品分组（一个源商品一个组）
  source_sku              TEXT NOT NULL,          -- 源商品 SKU（product_data_cache.sku）
  source_store_id         TEXT,                   -- 源店铺 ID（可为空=来自采集箱/1688）
  source_product_id       TEXT,                   -- 源商品 Ozon product_id
  name                    TEXT NOT NULL,          -- 优化后标题
  description             TEXT,                   -- 描述（4191 纯文本）
  rich_content            TEXT,                   -- 富内容（11254 JSON，可为空）
  description_category_id INTEGER NOT NULL,
  type_id                 INTEGER NOT NULL,
  primary_image           TEXT,                   -- 主图 URL
  images                  TEXT NOT NULL,          -- JSON 数组（加工后图片 URL）
  attributes              TEXT NOT NULL,          -- JSON 数组（v3 属性格式）
  video_url               TEXT,                   -- 视频 URL（可选）
  price_config            TEXT,                   -- JSON {salePrice,oldPrice,minPrice,templateId}
  default_stock           INTEGER NOT NULL DEFAULT 0,
  offer_id                TEXT,                   -- 素材自定义 offer_id（可为空，发布时按规则生成）
  status                  TEXT NOT NULL DEFAULT 'draft',  -- draft/ready/published/archived
  created_by              TEXT,
  created_at              TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at              TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_lm_group   ON listing_materials(group_id);
CREATE INDEX IF NOT EXISTS idx_lm_source  ON listing_materials(source_sku);
CREATE INDEX IF NOT EXISTS idx_lm_status  ON listing_materials(status);

-- ② 版本历史：每次编辑存一份完整快照
CREATE TABLE IF NOT EXISTS listing_material_versions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id  INTEGER NOT NULL REFERENCES listing_materials(id),
  version      INTEGER NOT NULL,
  snapshot     TEXT NOT NULL,        -- 完整素材 JSON 快照（含 name/description/images/attributes/price_config）
  change_note  TEXT,                 -- 变更说明
  created_by   TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(material_id, version)
);

-- ③ 发布记录：素材→店铺→上架任务 的追踪
CREATE TABLE IF NOT EXISTS listing_material_publishes (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id      INTEGER NOT NULL REFERENCES listing_materials(id),
  material_version INTEGER NOT NULL,
  store_id         TEXT NOT NULL,              -- 目标店铺 ID
  local_task_id    TEXT,                       -- 关联 follow_sell_tasks.local_task_id
  ozon_task_id     TEXT,                       -- Ozon 异步任务 ID
  status           TEXT NOT NULL DEFAULT 'pending',  -- pending/processing/success/failed
  error_message    TEXT,
  published_at     TEXT,
  created_at       TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(material_id, store_id)                -- 同一素材不能重复投同一店铺
);
CREATE INDEX IF NOT EXISTS idx_lmp_store ON listing_material_publishes(store_id);
```

### 3.2 复用现有表

| 表 | 用途 |
|---|---|
| `listing_templates` | 素材引用价格/水印/图片顺序配置（`price_config.templateId`） |
| `follow_sell_tasks` / `follow_sell_task_items` / `follow_sell_task_payloads` | 发布后沿用现有任务跟踪与快照 |
| `batch_upload_tasks` / `batch_upload_items` | 多素材→多店铺批量发布 |
| `product_data_cache` / `product_attributes_cache` | 生成素材时的源数据 |
| `ozon_meta_category_tree` / `ozon_meta_category_attributes` | 类目/属性元数据 |

## 4. 生成引擎

### 4.1 接口

```
POST /api/listing-materials/generate
body: {
  sourceSku: "5389811474",
  sourceStoreId: "store-yql04-...",      // 可选,留空则从采集箱/缓存读
  sourceType: "product",                // collect(默认,采集箱)/ product(Ozon 商品数据缓存)
  count: 3,                              // 生成份数（1~5）
  titleStrategy: ["marketing", "simple", "seo"],  // 标题风格
  aiRewrite: true,                       // 是否 AI 重写
  watermarkTemplateId: 1,                // 水印模板
  applyPoster: true,                     // 是否生成海报
  templateId: 1,                         // 价格模板
  defaultStock: 10,
  modelNamePrefix: "MSJ"                 // 型号名称前缀（可选）
}
```

### 4.2 处理流程

```
1. 拉取源数据
   buildSynthesizedFromCache(sourceSku) 或 productInfoListV3 → 完整 item
   + product_attributes_cache 取属性值与描述

2. 生成标题（count 份）
   - AI：扩展 enrichments/ai-rewrite.js，一次 prompt 输出 N 个风格变体
   - 模板：保留核心参数（型号/尺寸/材质/角度），变化修饰词库
   - 校验：标题长度 ≤ Ozon 限制；必须含核心关键词

3. 生成描述（count 份）
   - 基于原描述/富内容，AI 重写 N 版
   - 规范：真实参数（尺寸/压力/材料等）必须保留，只变营销文案
   - 同步生成 4191 纯文本与 11254 富内容 JSON

4. 图片加工（count 份）
   - 复用 prepareBundleItems 加工链：ai_rewrite → watermark → ai_poster → copy_ban
   - 每份素材使用不同的水印/海报模板、主图顺序
   - 加工后图片上传图床，素材中保存最终 URL

5. 属性差异化（count 份）
   - 必填属性自动填充：类型(8229)=type_id 对应类型、型号名称(9048)=变体码、品牌(85)=无品牌
   - 每份素材生成唯一型号名称（如 {prefix}{时间戳36进制}）
   - 卖家代码(9024) 留空，发布时按 offer_id 规则生成
   - 核心参数属性值必须真实，不得编造

6. 价格
   - 有 templateId：按 listing_templates 价格公式计算（复用 computePricesFromTemplate）
   - 无 templateId：使用源商品价格或手工指定

7. 保存
   - 生成 group_id = 源SKU
   - 逐份写入 listing_materials（status=draft）+ 首版本快照
```

### 4.3 标题风格模板（示例）

| 风格 | 模板 |
|---|---|
| marketing | 「{商品名} — {核心卖点}，{场景词}！{促销词}」 |
| simple | 「{类型} {型号} {核心参数}」 |
| seo | 「{类型} {核心参数} {场景词} купить — {品牌词}」 |

> 注意：所有变体必须基于真实商品参数，禁止编造不存在的卖点。

## 5. 审核与编辑

### 5.1 状态机

```
draft ──审核通过──▶ ready ──发布──▶ published
  ▲                  │
  └────编辑保存新版本──┘
archived（软删除/停用）
```

### 5.2 页面功能（`erp-backend-lite/web` 或 `httpcli` 新增「素材管理」菜单）

- **列表**：按源商品分组，展示组内多份素材、状态、目标店铺。
- **详情/预览**：标题、描述、富内容、图片、属性、价格。
- **编辑**：手动修改任意字段，保存产生新版本（版本历史可回溯）。
- **对比**：同组多份素材并排对比（标题/图片/属性差异）。
- **审核**：`draft → ready`。
- **发布**：选择 ready 素材 + 目标店铺 + 库存 → 发起上架。

## 6. 发布流程

### 6.1 单素材发布

```
POST /api/listing-materials/:id/publish
body: { storeId, defaultStock?, overridePrice? }
```

处理步骤：

1. 校验素材状态为 `ready`，且 `listing_material_publishes` 无 `(material_id, store_id)` 重复记录。
2. 调用 `listing-builder.js` 新增函数 `buildListingMessageFromMaterial(material, storeId, options)`：
   - 将素材字段转换为现有 `item` 结构（name/images/attributes/price/...）。
   - 复用 `buildListingMessage` 的强制字段注入逻辑（品牌=无品牌、型号名称=素材唯一码、卖家代码=`{sku}-{mmdd}-qx`）。
   - 图片直接使用素材中已加工 URL，**不再二次加工**（可配置 `reprocess:true` 走加工链）。
3. 走现有管线：
   - `prepareListing(message, storeId, store)`（图片已就绪，跳过 prepareBundleItems 或快速通过）
   - `commitListing(localTaskId, transformedItems, storeId, store)` → `opi.productImport`
   - `import-status-poller` 跟踪状态
4. 回写 `listing_material_publishes`（status=processing→success/failed，local_task_id、ozon_task_id）。
5. 成功后将素材状态置为 `published`。

### 6.2 批量发布（多素材→多店铺）

复用 `batch-upload` 框架：

```
POST /api/listing-materials/batch-publish
body: { assignments: [{ materialId, storeId, defaultStock }] }
```

- 后端将每个 assignment 转换为一条上架任务，写入 `batch_upload_tasks`（`store_ids` 聚合）。
- 处理逻辑复用 `batch-upload-poller` / `batch-image-poller`。
- 每个 assignment 的发布记录写入 `listing_material_publishes`。

## 7. 防同款合并（差异化保障）

Ozon 会自动合并同款商品卡片，素材机制从以下维度保证差异：

| 维度 | 手段 | 相关字段/模块 |
|---|---|---|
| 标题 | 每份素材标题不同（AI/模板重写） | `name` |
| 图片 | 水印/海报/主图顺序/裁剪不同 | `images` / `primary_image` |
| 型号名称 | 每份素材生成唯一变体码 | `attributes` 9048 |
| 卖家代码 | 发布时生成 `{sku}-{mmdd}-qx` 唯一 offer_id | `offer_id` |
| 描述/富内容 | 每份素材文案不同 | `description` / `rich_content` |
| 属性 | 不填“组合成类似产品(22390)”，避免被系统归组 | `attributes` |

> 注意：核心参数属性（尺寸、材料、压力等）必须保持真实一致，差异仅体现在营销类字段。

## 10. 落地阶段

### Phase 1：最小闭环

- 建 3 张表 + 迁移。
- 生成接口（模板化标题/图片乱序/唯一型号名称，AI 可选）。
- 支持两种数据源：`collect`（采集箱）与 `product`（Ozon 商品数据缓存，商品列表直接选 SKU）。
- 单素材发布到单店铺（复用现有管线）。
- 发布记录回写（失败可重试，成功/处理中拦截重复投放）。
- 简单列表/详情 API。

### Phase 2：完整编辑流（已实现 2026-10-24）

- 版本历史 + 编辑保存 API。
- 审核状态流 + 前端「素材管理」页面（列表/生成/详情预览/审核/发布/批量发布）。
- AI 多风格重写（`enrichments/ai-rewrite.js#rewriteVariants`，marketing/simple/seo/default）。
- 批量发布（复用 batch-upload 两阶段框架：`batch_upload_items.material_id` + `listing_material_publishes.batch_item_id` 回写）。

### Phase 3：数据驱动

- 素材 A/B 效果对比（曝光/点击/转化）。
- 图片高级差异化（背景/角度变换）。
- 基于效果自动推荐素材模板。

## 11. 风险与注意事项

1. **参数真实性**：AI 重写只允许修改营销文案，核心参数属性必须来自源数据，防止虚假宣传导致下架。
2. **同款合并**：差异化字段必须足够，否则 Ozon 会把不同店铺的同款合并成一张卡片。
3. **图片版权**：加工后的图片仍可能被 Ozon 识别为同图，必要时叠加不同水印/裁剪/背景。
4. **offer_id 唯一性**：发布时确保 `{sku}-{mmdd}-qx` 在目标店铺唯一（现有机制已保证）。
5. **素材复用边界**：同一素材投同一店铺禁止重复；不同店铺可投放同一素材，但需确认差异化仍足够。
