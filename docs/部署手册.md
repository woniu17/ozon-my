## 1. ERP 后端 + admin 后台（git 流程）

后端源码与 admin 前端源码均走 git 部署；admin 构建产物在**服务器上构建**。

```
本地:  修改 → git commit → git push origin main
服务器: cd /root/code/ozon-my && git pull
        cd erp-backend-lite/web && npm run build     # 服务器 node v22 + web/node_modules 可自行构建
        清理 src/public 根目录旧 admin-* 产物        # 见下方说明
        pm2 restart erp
```

### 清理旧构建产物

web 构建产物在 `erp-backend-lite/src/public/` 根目录（`admin-<hash>.js/css` + `admin.html`）。`src/public` 被 gitignore 不入库，旧 hash 文件会一直堆积，需手动清理：

```bash
cd /root/code/ozon-my/erp-backend-lite
NEW_JS=$(grep -o 'admin-[A-Za-z0-9_-]*\.js' src/public/admin.html | head -1)
NEW_CSS=$(grep -o 'admin-[A-Za-z0-9_-]*\.css' src/public/admin.html | head -1)
find src/public -maxdepth 1 \( -name 'admin-*.js' -o -name 'admin-*.css' \) \
  | grep -v -e "$NEW_JS" -e "$NEW_CSS" | xargs -r rm -f
```

> 注意：产物在 `src/public/` **根目录**，不在 `assets/` 子目录；`rm` 前先 `echo` 确认列表，别把 admin.html 引用的新 hash 文件删了。

### 约束与教训

- **禁止直接 rsync 源码到服务器**——会产生脏工作区；迁移时需 `git checkout -- .` + `git clean -fd erp-backend-lite` 清理。只有 git pull 是合法的源码更新方式。
- 纯前端改动（仅 web/ 下文件）其实不需要 pm2 restart：`express.static` 逐请求读盘且响应 `no-cache`，构建完刷新页面即生效。涉及后端代码（src/）必须 restart。
- 部署后验证：`pm2 status`（online）；`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:3001/health`；浏览器刷新 `/admin` 确认引用新 hash 文件。

## 2. miniapp H5（本地构建 + rsync 产物）

miniapp 是 uni-app 项目。**服务器上没有 miniapp/node_modules，无法在服务器构建**，只能本地构建后 rsync 产物（与 admin 后台相反）。

```bash
# 1. 本地编译（产物: miniapp/dist/build/h5/，含 index.html + assets/ + static/）
cd miniapp && npm run build:h5

# 2. rsync 到服务器（目标目录已 gitignore，不产生脏工作区）
rsync -av --delete dist/build/h5/ \
  root@nuc.yochylin.com:/root/code/ozon-my/erp-backend-lite/src/public/miniapp/
```

- **无需 pm2 restart**、无需 git 操作——静态文件由后端 `express.static` 直接服务。
- `--delete` 会移除服务器上已被新构建淘汰的旧 hash 文件，无需手动清理。
- 部署后刷新 `https://yochylin.com:17443/miniapp/` 验证。
- 生产 H5 用相对路径同源请求（`src/config.js` 中 `BASE_URL=''`），免跨域；改动接口地址时注意 dev/prod 两套配置。

> 「禁止 rsync 源码」针对的是**源码文件**；rsync 构建产物到 gitignored 的 `src/public/miniapp/` 正是本链路的既有部署方式。

## 4. 后端接口变更时的联动

| 改动类型 | 需要的操作 |
| --- | --- |
| 仅后端（src/） | git 流程（第 1 节）+ pm2 restart |
| 仅 admin 前端（web/） | git 流程（第 1 节），restart 可选 |
| 仅 miniapp（miniapp/） | 本地构建 + rsync（第 2 节） |
| 后端接口 + miniapp 同时改 | 先部署后端（第 1 节），再 rsync miniapp（第 2 节）；顺序反了会出现新前端调旧接口 |
