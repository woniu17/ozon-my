# 图床 + 水印加工功能 — 概要设计文档

> 版本：v1.0
> 日期：2026-07-28
> 模块：ERP 后端（erp-backend-lite）上架加工链
> 关联 Spec：`.trae/specs/add-image-host-with-watermark/`

---

## 1. 背景与目标

### 1.1 现状问题
ERP 后端的 `prepareBundleItems` 加工链中原本存在一个水印步骤（`enrichments/watermark.js`），但实现是"标记模式"——只给 `item.images[i]._watermarked = true` 后透传，并未真正下载图片、渲染水印、替换为可被 Ozon OPI 拉取的公网 URL。

这导致：
- 三个上架入口（按筛选自动上架 / 批量均衡上架 / 上架预览一键上架）实际提交给 OPI 的仍是原 Ozon/第三方图片链接
- 存在搬运判定风险
- `watermark_templates` 表的配置形同虚设

### 1.2 设计目标
让水印加工链真正生效：
1. **真下载**：下载原图到内存
2. **真渲染**：按 `watermark_templates.config` 用 sharp 渲染水印（text / border / image 三种类型）
3. **真落盘**：保存到 ERP 后端 `public/images/{sku}/{md5(url)}.jpg`
4. **真替换**：通过 `IMAGE_HOST_BASE_URL` 拼接公网 URL 替换 `item.images[i].file_name`
5. **三入口共用**：所有上架入口复用同一套逻辑，上游调用方无感
6. **失败降级**：任一环节失败透传原图，不阻断业务

### 1.3 非目标
- 不涉及水印模板的前端管理界面（模板通过现有管理后台或 SQL 维护）
- 不修改 `watermark_templates` 表结构（仅约定 `config` JSON schema）
- 不实现图片 CDN 加速（直接通过 ERP 后端反代访问）
- 不实现分布式图片存储（单机本地落盘）

```

                  │

```

### 3.2 三个上架入口的统一路径

| 入口 | HTTP 路由 | message 构造路径 | 是否注入水印字段 |
|------|-----------|------------------|------------------|
| 按筛选自动上架 | `POST /admin/api/batch-upload/auto-pick` | `batch-upload-poller.executeBatchItem` → `buildListingMessage` | 是（buildListingMessage 注入） |
| 批量均衡上架 | `POST /admin/api/batch-upload` | `batch-upload-poller.executeBatchItem` → `buildListingMessage` | 是（buildListingMessage 注入） |
| 上架预览一键上架 | `POST /ozon/products/import` | `products.js` 直接传 `req.body` 给 `executeListing` | 是（executeListing 兜底注入） |

> 关键设计：`executeListing` 中也复用了 `buildListingMessage` 的模板读取逻辑，确保三条路径行为一致。

## 4. 配置项

### 4.1 环境变量

| 变量名 | 必填 | 默认值 | 说明 |
|--------|------|--------|------|
| `IMAGE_HOST_BASE_URL` | 否 | `''` | ERP 后端公网反代基址。不配置时水印功能降级为透传（即使模板 `applyWatermark=true` 也不渲染）。配置示例：`https://2.tencent.yochylin.com:17443`（不带尾斜杠） |

### 4.2 上架模板字段（`listing_templates.config_json`）

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `applyWatermark` | boolean | `false` | 是否对图片应用水印加工 |
| `watermarkTemplateId` | number \| null | `null` | 关联 `watermark_templates.id`，为空时不渲染 |

### 4.3 水印模板字段（`watermark_templates.config`）

JSON 结构约定如下：

```json
{
  "type": "text|border|image",
  "text":   { "content": "string", "fontSize": 32, "color": "#FFFFFF", "opacity": 0.6, "position": "bottom-right" },
  "border": { "width": 10, "color": "#000000", "opacity": 0.5 },
  "image":  { "url": "https://...", "scale": 0.2, "opacity": 0.5, "position": "bottom-right" }
}
```

- `position` 枚举：`top-left` / `top-right` / `bottom-left` / `bottom-right` / `center`
- `opacity` 范围 0–1
- `type=text` 时 `text` 必填；`type=border` 时 `border` 必填；`type=image` 时 `image` 必填
- 字段缺失时使用默认值（如 `fontSize=32`、`opacity=0.6`、`position='bottom-right'`）

## 5. 数据存储

### 5.1 数据库表（无结构变更）

#### `watermark_templates` 表
保持现有结构不变，仅约定 `config` 字段的 JSON schema：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 模板 ID |
| `name` | TEXT | 模板名称 |
| `config` | TEXT(JSON) | 水印配置 JSON（schema 见 4.3） |
| `is_default` | INTEGER | 是否默认模板 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

#### `listing_templates` 表
`config_json` 字段中新增两个可选字段：`applyWatermark`、`watermarkTemplateId`。未配置时视为 `false` / `null`。

### 5.2 文件系统

```
erp-backend-lite/src/public/
└── images/
    └── {sku}/                       # SKU 子目录(sanitize 后,非[a-zA-Z0-9_-]字符替换为 _)
        ├── {md5(url1)}.jpg          # 处理后的图片(JPG 格式)
        ├── {md5(url2)}.jpg
        └── ...
```

- **命名规则**：`{md5(原图URL)}.jpg`，保证幂等
- **目录创建**：自动 `mkdirSync(subDir, { recursive: true })`
- **访问路径**：通过 `express.static(PUBLIC_DIR)` 自动暴露，URL 为 `${IMAGE_HOST_BASE_URL}/images/{sku}/{hash}.jpg`
- **Git 忽略**：`src/public/images/` 已加入 `.gitignore`，产物不入库

## 6. 降级策略

本功能采用"尽力而为 + 透传降级"策略，确保不阻断上架业务：

| 失败场景 | 降级行为 | 影响范围 | 日志级别 |
|----------|----------|----------|----------|
| `IMAGE_HOST_BASE_URL` 未配置 | 整批透传原图 | 整批 | warn |
| `sharp` 模块未安装 | 整批透传原图 | 整批 | warn |
| `watermarkTemplateId` 为空 | 整批透传原图 | 整批 | warn |
| 水印模板不存在 / config 无效 | 整批透传原图 | 整批 | warn |
| 下载原图失败（网络/404/超时） | 该图透传原图 | 单图 | warn |
| sharp 渲染失败（格式不支持/SVG 异常） | 该图透传原图 | 单图 | warn |
| 落盘失败（磁盘满/权限错误） | 该图透传原图 | 单图 | warn |
| 加工链整体异常 | 降级为透传未加工的 items | 整批 | error |

### 关键原则
1. **单图失败不影响其他图**：try-catch 在图片循环内，失败仅透传该图
2. **整批降级时不进入单图循环**：前置检查失败直接 `return items`
3. **保留 `img.default` 字段不变**：确保 `transformItemForPortal` 仍能正确识别主图
4. **幂等性**：同一 URL 重复处理时直接复用已落盘文件，跳过下载与渲染

## 8. 部署与启用

### 8.1 启用步骤

1. **安装依赖**：
   ```bash
   cd erp-backend-lite
   npm install
   ```
   `sharp` 已升级为必装依赖，会自动安装。

2. **配置环境变量**：
   在 `.env` 中配置：
   ```env
   IMAGE_HOST_BASE_URL=https://你的公网反代地址
   ```
   要求：
   - 必须是公网可访问的根 URL（Ozon OPI 服务器需要能拉取）
   - 不带尾斜杠
   - 已通过 nginx 等反代指向 ERP 后端的 `src/public/` 目录

3. **创建水印模板**：
   在管理后台或直接 SQL 插入 `watermark_templates` 记录，`config` 字段按 4.3 节 schema 填写。

4. **配置上架模板**：
   在 `listing_templates.config_json` 中设置：
   ```json
   {
     "applyWatermark": true,
     "watermarkTemplateId": 1
   }
   ```

5. **重启 ERP 后端**：
   ```bash
   pm2 restart erp-backend
   ```

### 8.2 验证方式

- 触发任意上架入口，检查 `follow_sell_task_payloads` 表中 `stage='opi_request'` 的 payload，`images` 字段应为 `${IMAGE_HOST_BASE_URL}/images/{sku}/{hash}.jpg` 格式
- 检查 `erp-backend-lite/src/public/images/{sku}/` 目录下应有对应图片文件
- 重复触发同一 SKU 上架，文件数量不增加（幂等性验证）

## 9. 风险与约束

| 风险 | 缓解措施 |
|------|----------|
| 公网反代不可用时 OPI 拉取失败 | 确保 ERP 后端反代高可用；监控图片访问日志 |
| 磁盘空间持续增长 | 定期清理 `public/images/` 下过期文件（后续可加定时任务） |
| 下载源站图片被限流 | 30s 超时 + 失败透传，不重试 |
| sharp 原生编译失败 | sharp 0.33+ 提供 prebuilt binaries，多数环境无需编译 |
| 并发下载对源站压力 | 当前无并发限制（单批次串行处理），如需可后续加并发控制 |
