# 微信小程序·订单处理 — 功能设计

> 版本:v1.0(2026-09-19,设计定稿待实施)
> 模块:新增 miniapp/(uni-app 小程序),复用 erp-backend-lite 全部 REST API
> 前置:docs/采购订单-Ozon订单关联管理-功能设计.md、docs/扫描发货-功能设计.md
> 关联决策(2026-09-19 用户确认):
> ① 技术栈 **uni-app + Vue 3 + Vite**(与 web 前端同构,api 层可移植);
> ② 服务器为**自托管主机**(nuc.yochylin.com,家庭宽带,域名未备案);
> ③ 一期范围:**订单查看 + 采购(含平台订单导入) + 备货**。

***

## 1. 背景与目标

订单处理目前只能在电脑端(admin web)操作。实际业务中,采购、备货、查单经常发生在脱离电脑的场景(仓库打包、外出、手机随手处理)。目标:微信小程序作为**第四个客户端**(与 admin web、浏览器插件、飞书通知并列),一期覆盖订单处理核心链路:

- **查看订单**:状态 tabs、搜索、分页、详情(产品行 + 采购关联 + 轨迹);
- **进行采购**:平台订单浏览勾选导入 + 手填单号 + 修改已有采购分摊(与 web 端 2026-09-19 上线的新语义一致);
- **备货处理**:同步订单 → 备货 → 同步采购物流。

**非目标(一期明确排除)**:打印面单(依赖本地打印代理)、扫描发货(相机扫码录重,二期)、价格管理、历史订单、金额统计条、飞书配置。

***

## 2. 现状调研结论(可复用资产)

后端 API 全部现成,**一期后端零必须改动**:

| 小程序功能 | 复用 API | 备注 |
| --- | --- | --- |
| 登录 | `POST /auth/login-password` | 手机号+密码 → JWT(7 天),与 web 同构 |
| 状态 tabs + 计数 | `GET /admin/api/order-process/tabs` | 直接渲染 |
| 订单列表/搜索/分页 | `GET /admin/api/order-process/list` | `globalKeyword` 全局搜索 7 类字段,模糊默认 |
| 订单详情 | `GET /admin/api/order-process/detail/:id` | 产品行 + 采购关联(行级 link)+ 轨迹 |
| 提交采购 | `POST /order-process/purchase` | auto/manual 双模式,含平台商品 items_json |
| 修改已有采购分摊 | `POST /order-process/purchase-alloc` | 2026-09-19 新上线,行级归属唯一 |
| 取消采购关联 | `POST /order-process/unlink` | 冲回 + 聚合重算 |
| 清空采购 | `POST /order-process/purchase/clear` | |
| 拼单查询 | `GET /order-process/purchase/lookup` | 采购单已关联包裹提示 |
| 备货 | `POST /order-process/ship` | 幂等(alreadyShipped),前置 wait_ship + Ozon awaiting_packaging |
| 同步订单 | `POST /order-process/sync-package` | 单包裹强制同步 + 应计 |
| 同步采购物流 | `POST /order-process/sync-package-purchase-logistics` | 行级按钮,有 purchaseLinks 才显示 |
| 平台订单列表 | `GET /admin/api/platform-orders/:platform` | 服务器 cloakbrowser 直取,支持多账号 |
| 平台订单搜索 | `GET /admin/api/platform-orders/:platform/search` | 按单号精确搜,跨账号 |
| 平台登录态探测 | `GET /admin/api/platform-orders/status` | 未登录警示 |
| 已关联防重勾选 | 前端逻辑移植 | web 端 `restoredSnKeys`(platform:sn 键集合) |

**采购语义约定(与 web 端 5893fbf 对齐,小程序必须同口径)**:
- 「自动填写金额」勾选 = 平台订单支付金额按数量加权分摊;
- 取消勾选手填 = **修改已有采购单分摊到本包裹的金额**,不新增采购单(`purchase-alloc`);
- 手动录入 tab 无单号 = 合法手工采购场景(保持)。

## 3. 总体架构

### 3.1 系统拓扑

```
┌─────────────────────┐         ┌──────────────────────────────┐
│  微信小程序(uni-app) │  HTTPS  │   云服务器(轻量,备案域名)     │
│  ┌───────────────┐  │ ──────► │   nginx :443(TLS 终结)        │
│  │ Vue3 运行时    │  │         │   反代 + 共享密钥头 ──────────┼──┐
│  │ api/(wx适配)  │  │         └──────────────────────────────┘  │
│  │ pages/×4      │  │                                           ▼ 公网
│  └───────────────┘  │                            ┌─────────────────────────┐
└─────────────────────┘                            │ nuc.yochylin.com(自托管) │
                                                   │ nginx → erp-backend-lite │
      开发期(不等备案):                              │ :3001(Koa) → SQLite     │
      开发者工具「不校验合法域名」                     │ cloakbrowser(平台登录态) │
      + 真机调试模式,直连 nuc 公网端点                └─────────────────────────┘
```

### 3.2 设计原则

- **瘦客户端**:业务逻辑(分摊算法、状态流转、聚合重算)全部在后端,小程序只做展示与提交,不复制任何计算逻辑;
- **API 同构**:`miniapp/src/api/order.js` 与 `web/src/api/order-process.js` 接口定义一一对应,后端改接口时两端同步维护;
- **web 端不受影响**:不新增、不修改任何现有后端路由。

## 4. 网络与部署(自托管主机的关键路径)

**约束**:小程序正式版要求 request 合法域名 = HTTPS + ICP 备案;自托管主机(家庭宽带)**无法直接备案**。

### 4.1 路径分两阶段

| 阶段 | 通道 | 说明 |
| --- | --- | --- |
| 开发期(立即) | 小程序直连 `https://yochylin.com:17443`(现有公网入口,与 admin web 同源;2026-09-19 实测:`nuc.yochylin.com` 443 不通,`yochylin.com:17443` 可用) | 开发者工具勾选「不校验合法域名」;真机调试模式同样跳过校验 |
| 发布期(备案后) | 小程序 → 云服务器(备案域名,TLS)→ 反代 → nuc | 购最低配轻量云(¥50-100/年),nginx 终结 TLS 后转发 nuc 公网端点,加共享密钥头 `X-Proxy-Secret` 防扫描直连 |

### 4.2 备案并行启动(不阻塞开发)

1. 域名接入云服务商(阿里云/腾讯云)→ 提交 ICP 备案(约 1-2 周);
2. 备案通过后:云服务器 nginx 配 TLS 证书(Let's Encrypt 或云免费证书)→ 反代 nuc;
3. 微信小程序后台(mp.weixin.qq.com)配置 request 合法域名;
4. 小程序账号:**个人主体**即可(工具类目),个人主体小程序支持 HTTPS request,满足本需求。

### 4.3 反代安全

- 云→nuc 转发携带共享密钥头,nuc nginx 校验后才放行到 erp;
- 应用层已有 JWT 鉴权,双层防护;密钥走 `.env`,不进仓库。

## 5. 鉴权设计

```
登录页(手机号+密码)
   │ POST /auth/login-password
   ▼
JWT accessToken(7d) ──► wx.setStorageSync('token')
   │
   ▼
request.js 拦截器:wx.request header 注入 Authorization: Bearer <token>
   │
   ├─ 200 ──► 正常返回
   └─ 401(AUTH_EXPIRED)──► 清 token → 重定向登录页
```

- 与 web 端完全同构,后端零改动;token 过期重新登录即可(个人应用无需 refresh token);
- **二期可选**:`POST /auth/wx-login`(`wx.login` code → code2session → openid 白名单 → 签发同款 JWT),免密登录。

## 6. 页面结构详设

### 6.1 页面清单(4 页 + 2 弹层)

| 页面 | 路径 | 核心 |
| --- | --- | --- |
| 登录 | `pages/login/` | 手机号+密码,记住手机号 |
| 订单列表(首页) | `pages/orders/` | tabs + 搜索 + 卡片流 + 分页 |
| 订单详情 | `pages/order-detail/` | 产品行 + 采购关联 + 行级操作 |
| 采购弹层(全屏) | `pages/purchase/` 或全屏 popup | 分步流程(§6.3) |
| 备货确认 | 弹窗 | 货件号/商品数确认 → POST /ship |
| 同步结果 | toast/横幅 | 同步订单/物流的结果反馈 |

### 6.2 订单列表页

```
┌────────────────────────────────┐
│ 🔍 搜索框(全局模糊,7类字段)      │
│ [待处理 12] [待打单 8] [交运中…] │ ← 横向滚动 tabs,带计数,复用 /tabs
│ [采购状态▾] [店铺▾]              │ ← 筛选(下拉)
├────────────────────────────────┤
│ ┌────────────────────────────┐ │
│ │ [图] 商品标题(省略号)        │ │ ← 卡片:货件号+母子件徽标
│ │ 78345175-0268-1 · YQL02    │ │   店铺名、数量、金额
│ │ ×2  ¥56.00  [已采购] 待打单  │ │   采购状态徽标 + 状态
│ └────────────────────────────┘ │
│ …(下拉刷新 / 上拉触底加载)      │
└────────────────────────────────┘
```

- 复用 `/list` 的 `tab/keyword/storeId/purchaseStatus/page/pageSize/globalKeyword/globalMode`;
- 卡片点击 → 详情;操作按钮收敛到详情页(列表保持纯浏览,符合手机习惯)。

### 6.3 采购弹层(分步流程,替代 web 三栏平铺)

```
Step 1  已有采购(有则显示)
┌────────────────────────────────┐
│ 3316392554031013394 · 1688     │ ← 卡片:单号/平台/本包裹分摊
│ 分摊 ¥12.80   [改分摊] [删除]   │   删除=unlink(冲回),改分摊→Step 3
└────────────────────────────────┘

Step 2  选平台订单
┌────────────────────────────────┐
│ [1688·linqx] [1688·chenlin]    │ ← 平台×账号 tab,复用 /status 展开
│ [拼多多] [淘宝]  ⚠未检测到登录态 │ ← 警示:恢复登录需在服务器/电脑端
│ ┌────────────────────────────┐ │
│ │☑ 单号 ¥金额 时间 [图]商品…   │ │ ← /platform-orders/:platform
│ │☐ …                         │ │   已关联单禁止重复勾选(restoredSnKeys)
│ └────────────────────────────┘ │
│ 底部条:已选 N 单 合计 ¥xxx [下一步]│
│ 搜索框:按单号精确搜(补全场景)    │ ← /:platform/search
└────────────────────────────────┘

Step 3  确认分摊并提交
┌────────────────────────────────┐
│ ☑ 自动填写金额(按数量加权)       │
│ ┌────────────────────────────┐ │
│ │ [图] SKU ×2   ¥12.80 [输入] │ │ ← auto:只读预览;manual:可输入,
│ │ [图] SKU ×1   ¥6.40  [输入] │ │   切换时回填当前分摊(与 web 一致)
│ └────────────────────────────┘ │
│ 国内快递单号(选填,填了视为已发货)│
│ [提交采购]                      │ ← POST /purchase(auto)
└────────────────────────────────┘
   manual + 无单号 + 无新勾选 + 有已有采购
   → POST /purchase-alloc(修改分摊,确认弹窗显示新旧金额)
```

- 提交后提示「包裹已流转待打单发货」并刷新列表;
- 拼单检测:勾选单号已关联其他包裹时,弹确认「追加关联」(复用 `/purchase/lookup`)。

### 6.4 订单详情页

- **产品行**:图(点击 `previewImage` 放大)、标题、SKU、数量、称重重量;
- **采购关联卡**:单号、平台、分摊金额、国内物流单号 + 最新轨迹摘要、采购商品缩略;
- **操作按钮组**(基于行级 `operateStatus`,与 web 831ecb6 规则一致):
  - `wait_process`:采购(主按钮);
  - 有 `purchaseLinks` 且非待处理:同步采购物流;
  - 全状态:同步订单、备货(`wait_ship` 时备货为主操作);
  - 备货确认弹窗 → `POST /ship` → 成功/幂等(alreadyShipped)反馈。

## 9. 风险与约束

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 备案周期 1-2 周且可能被驳回 | 发布延期 | 开发期直连 nuc 不受影响;域名资料提前准备 |
| 云反代引入额外链路 | 延迟 + 单点 | 最低配轻量云足够(纯转发);nuc 直连通道保留为开发回退 |
| cloakbrowser 平台登录态失效 | Step2 拉不到平台订单 | /status 探测 + 显式警示;登录恢复引导到电脑端(web 端现有流程) |
| 手机小屏操作复杂采购(多行分摊) | 误操作 | 分步流程 + 提交前确认弹窗(新旧金额对比);复杂拼单建议电脑端处理 |
| 个人主体小程序审核 | 类目/功能被质询 | 工具类目 + 内部使用说明;不加支付/社交等敏感能力 |
| api 双端维护成本 | 接口漂移 | order.js 同构移植,注释标明与 web 端的对应关系 |
