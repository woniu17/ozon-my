# Ozon 推送通知

> 本栏目介绍了如何开启推送通知，从而从 Ozon 接收事件信息到您的服务器中。

通过推送通知，Ozon 可主动向您的服务器推送以下事件信息：

- 新发件的创建
- 发件取消
- 发件状态的变化
- 发件快递或装运日期变化

此外，您也可以收到由于您的服务器不可用而未被送达的消息和通知。

## 1. 如何连接

### 1.1 申请流程

> 您的服务器应该根据 REST API 标准和文档中规定的错误代码来发送回应。如果您的服务器回应偏离了所需的结构，通知发送可能会被暂停。

要接收通知，请发送请求至 [sapi-push@ozon.ru](mailto:sapi-push@ozon.ru)。在申请中请注明：

- 您的 `seller_id`。
- 向其发送通知的服务器 URL 地址。例如：`https://www.example.com/api/method`。
- 您想收到的 [通知清单](#2-通知类型概览)。

三个工作日内您的服务器将被绑定。

### 1.2 发送通知的 IP 地址

Ozon 从以下 IP 段向您的服务器发送通知，请确保您的服务器/防火墙允许以下来源的入站请求：

- `195.34.21.0/24`
- `185.73.192.0/22`
- `91.223.93.0/24`

### 1.3 连接检查请求

#### Ozon 发送的内容

```json5
{
  "message_type": "string",
  "time": "2019-08-24T14:15:22Z"
}
```

| 参数           | 类型     | 形式        | 描述                    |
| -------------- | -------- | ----------- | ----------------------- |
| `message_type` | string   | —           | 通知类型 — `TYPE_PING`。 |
| `time`         | string   | date-time   | 以 UTC 格式发送通知的日期和时间。 |

#### 您的服务器应该返回的内容

**成功收到通知**：返回 HTTP 200，回答体如下：

```json5
{
  "version": "string",
  "name": "string",
  "time": "2019-08-24T14:15:22Z"
}
```

| 参数      | 类型       | 形式        | 描述                                  |
| --------- | ---------- | ----------- | ------------------------------------- |
| `version` | string     | —           | 程序版本。                            |
| `name`    | string     | —           | 程序名称。                            |
| `time`    | string     | date-time   | 以 UTC 格式发送通知的日期和时间。 |

**发生错误**：返回 HTTP 4xx 或 5xx 组代码，回答体如下：

```json5
{
  "error": {
    "code": "ERROR_UNKNOWN",
    "message": "错误",
    "details": null
  }
}
```

| 参数      | 类型   | 形式 | 描述                                                                                                                              |
| --------- | ------ | ---- | --------------------------------------------------------------------------------------------------------------------------------- |
| `error`   | object | —    | 有关错误的信息。                                                                                                                  |
| `code`    | string | —    | 错误代码：`ERROR_UNKNOWN`（未知错误）、`ERROR_PARAMETER_VALUE_MISSED`（未指定参数值）、`ERROR_REQUEST_DUPLICATED`（重复请求）。 |
| `message` | string | —    | 详细的错误描述。                                                                                                                  |
| `details` | string | —    | 更多信息。                                                                                                                        |

### 1.4 连接时的错误代码

| 错误                    | 描述                       | 解决方法                                                                      |
| ----------------------- | -------------------------- | ----------------------------------------------------------------------------- |
| `REQUEST_ERROR`         | 请求未发送，无法连接到指定地址。 | 请检查您的服务是否正常运行。                                                  |
| `REQUEST_TIMEOUT`       | 请求超时。                  | 增加请求的等待时间。                                                          |
| `SERVER_FAULT`          | 您的服务返回了服务器内部错误。 | 请检查服务器日志，更新服务器软件，增加分配的资源或联系服务器管理员。            |
| `STATUS_CODE_NOT_OK`    | 服务的 HTTP 响应状态码不为 200。 | 请检查传递的状态码。                                                          |
| `EMPTY_BODY`            | 响应体为空或不存在。        | 请检查服务器的响应是否正确生成，以及数据是否正确传递。                          |
| `INVALID_BODY`          | 响应体格式不正确。          | 请检查响应格式，并确保 `Content-Type` 头部为 `application/json`。             |
| `INVALID_JSON`          | 解析或验证 JSON 数据时出错。 | 请检查 JSON 数据的正确性，并修正语法错误。                                    |
| `WRONG_RESULT_FIELD`    | 您的服务返回的响应体不符合模板。 | 请检查响应格式是否符合模板（[了解更多](#13-连接检查请求)）。                     |
| `WRONG_RESULT_TIME_FIELD` | 响应体中的 `time` 字段不正确。 | 请检查响应中的时间格式。                                                      |

### 3.2 TYPE_NEW_POSTING — 新的发货

> 如果订单付款延迟，那么 `in_process_at` 字段可能为空。您可以通过 `POST /v3/posting/fbs/get` 的 `result.in_process_at` 字段查看发运日期。

通知仅适用于 FBS 和 rFBS 货件：

```json
{
  "message_type": "TYPE_NEW_POSTING",
  "posting_number": "24319409-0021-1",
  "products": [
    {
      "sku": 147451939,
      "offer_id": "",
      "quantity": 1
    }
  ],
  "in_process_at": "2021-01-26T06:56:36.294Z",
  "warehouse_id": 12850503335000,
  "shipment_date": "2021-01-26T06:56:36.294Z",
  "tpl_integration_type": "3pl_tracking",
  "is_express": false,
  "tracking_number": "ZZV-23",
  "delivery_date_begin": "2025-01-26T06:56:36.294Z",
  "delivery_date_end": "2025-01-26T06:56:36.294Z",
  "seller_id": 1
}
```

| 参数                   | 类型    | 形式       | 描述                                                                                                       |
| ---------------------- | ------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| `message_type`         | string  | —          | 通知类型 — `TYPE_NEW_POSTING`。                                                                            |
| `posting_number`       | string  | —          | 发货货号。                                                                                                  |
| `products`             | array   | —          | 商品信息。                                                                                                  |
| `sku`                  | integer | int64      | Ozon 系统中的商品识别码 SKU。                                                                              |
| `quantity`             | integer | int64      | 商品数量。                                                                                                  |
| `in_process_at`        | string  | date-time  | 商品开始处理的日期和时间（UTC）。                                                                          |
| `warehouse_id`         | integer | int64      | 仓库标识符。                                                                                                |
| `shipment_date`        | string  | date-time  | 必须收取货件的日期和时间。                                                                                  |
| `tpl_integration_type` | string  | —          | 快递服务集成类型：`ozon`（Ozon 快递）、`3pl_tracking`（集成服务快递）、`non_integrated`（第三方物流）、`aggregator`（Ozon 合作物流伙伴）、`hybryd`（俄罗斯邮政配送）。 |
| `is_express`           | boolean | —          | express 配送标志。                                                                                         |
| `tracking_number`      | string  | —          | 货件跟踪号。                                                                                               |
| `delivery_date_begin`  | string  | date-time  | 快递开始日期和时间。                                                                                       |
| `delivery_date_end`    | string  | date-time  | 快递结束日期和时间。                                                                                       |
| `seller_id`            | integer | int64      | 卖家识别号。                                                                                                |

### 3.3 TYPE_POSTING_CANCELLED — 发货取消

通知仅适用于 FBS 和 rFBS 货件：

```json
{
  "message_type": "TYPE_POSTING_CANCELLED",
  "posting_number": "24219509-0020-1",
  "products": [
    {
      "sku": 147451959,
      "quantity": 1
    }
  ],
  "old_state": "posting_transferred_to_courier_service",
  "new_state": "posting_canceled",
  "changed_state_date": "2021-01-26T06:56:36.294Z",
  "reason": {
    "id": 0,
    "message": "string"
  },
  "warehouse_id": 0,
  "seller_id": 15
}
```

| 参数                 | 类型    | 形式       | 描述                                              |
| -------------------- | ------- | ---------- | ------------------------------------------------- |
| `message_type`       | string  | —          | 通知类型 — `TYPE_POSTING_CANCELLED`。             |
| `posting_number`     | string  | —          | 发货货号。                                        |
| `products`           | array   | —          | 商品信息。                                        |
| `sku`                | integer | int64      | Ozon 系统中的商品识别码 SKU。                     |
| `quantity`           | integer | int64      | 商品数量。                                        |
| `old_state`          | string  | —          | 发货的上一个状态。                                |
| `new_state`          | string  | —          | 发货的新状态：`posting_canceled`（已取消）。      |
| `changed_state_date` | string  | date-time  | 发货更改的日期和时间（UTC）。                     |
| `reason`             | object  | —          | 取消原因的信息。                                  |
| `id`                 | integer | int64      | 取消原因的识别号。                                |
| `message`            | string  | —          | 取消原因。                                        |
| `warehouse_id`       | integer | int64      | 储存该批发货的仓库的识别号。                      |
| `seller_id`          | integer | int64      | 卖家识别号。                                      |

#### 发货状态枚举值

- `posting_acceptance_in_progress` — 正在验收
- `posting_created` — 已创建
- `posting_transferring_to_delivery` — 发给快递
- `posting_in_carriage` — 在运输途中
- `posting_not_in_carriage` — 未在运输中
- `posting_in_client_arbitration` — 快递会员仲裁
- `posting_on_way_to_city` — 发往城市途中
- `posting_transferred_to_courier_service` — 转交给快递员
- `posting_in_courier_service` — 快递员正在路上
- `posting_on_way_to_pickup_point` — 正发往取货点
- `posting_in_pickup_point` — 在取货点
- `posting_conditionally_delivered` — 暂时送到
- `posting_driver_pick_up` — 在司机那儿
- `posting_not_in_sort_center` — 集散中心未收到

### 3.5 TYPE_CUTOFF_DATE_CHANGED — 发货的装运日期改变

> 通知在测试模式下工作。我们建议您使用 `POST /v3/posting/fbs/get` 在字段 `result.shipment_date` 检查发货日期。
>
> 字段 `new_cutoff_date` 可能会出现空白，因为快递间隔已经被删除。请等到新的日期被确定下来——之后新的通知就会到来。

> 有时，这种类型的通知可能在备货完成后才到达——请忽略之。

通知仅适用于 FBS 和 rFBS 货件：

```json
{
  "message_type": "TYPE_CUTOFF_DATE_CHANGED",
  "posting_number": "24219509-0020-2",
  "new_cutoff_date": "2021-11-24T07:00:00Z",
  "old_cutoff_date": "2021-11-21T10:00:00Z",
  "warehouse_id": 0,
  "seller_id": 15
}
```

| 参数              | 类型    | 形式       | 描述                                  |
| ----------------- | ------- | ---------- | ------------------------------------- |
| `message_type`    | string  | —          | 通知类型 — `TYPE_CUTOFF_DATE_CHANGED`。 |
| `posting_number`  | string  | —          | 发货号。                              |
| `new_cutoff_date` | string  | date-time  | 新的装运日期和时间（UTC）。           |
| `old_cutoff_date` | string  | date-time  | 上一个装运日期和时间（UTC）。        |
| `warehouse_id`    | integer | int64      | 储存该批发货的仓库的识别号。          |
| `seller_id`       | integer | int64      | 卖家识别号。                          |

### 3.6 TYPE_DELIVERY_DATE_CHANGED — 发货快递日期改变

> 如果货件中的商品按 rFBS 和 FBS 模式销售，则会收到通知。
>
> 字段 `new_delivery_date_begin` 和 `new_delivery_date_end` 在 rFBS 计划下出售时可能为空，因为快递间隔已经被删除。等到新的日期被确定下来——之后新的通知就会到来。


## 4. 您服务器的回复

### 如果成功收到通知

如果通知被成功处理，服务器应该返回 HTTP 200 代码，回答体如下：

```json5
{
  "result": true
}
```

| 参数     | 类型    | 形式 | 描述        |
| -------- | ------- | ---- | ----------- |
| `result` | boolean | —    | 通知已收到。 |

### 如果发生错误

如果在通知处理过程中发生错误，服务器应该返回 HTTP 4xx 或 5xx 组代码，回答体如下：

```json5
{
  "error": {
    "code": "ERROR_UNKNOWN",
    "message": "ошибка",
    "details": null
  }
}
```

| 参数      | 类型   | 形式 | 描述                                                                                                                              |
| --------- | ------ | ---- | --------------------------------------------------------------------------------------------------------------------------------- |
| `error`   | object | —    | 关于错误的信息。                                                                                                                  |
| `code`    | string | —    | 错误码：`ERROR_UNKNOWN`（不明错误）、`ERROR_PARAMETER_VALUE_MISSED`（未指定参数值）、`ERROR_REQUEST_DUPLICATED`（重复请求）。 |
| `message` | string | —    | 详细的错误描述。                                                                                                                  |
| `details` | string | —    | 更多信息。                                                                                                                        |

## 5. 重新发送通知

### 重发时间间隔

如果通知没有送达，系统会在几秒钟后尝试再发送几次请求。两次尝试中间的间隔时间将逐渐增加。当达到最大值 10 分钟时，每 10 分钟将会有 5 次多的尝试。

### 自动暂停发送通知

如果信息仍然不能被送达，发送请求的尝试将停止。

所有通知的发送将在满足以下任何一个条件时暂停：

- 服务不可用；
- 服务在 24 小时内持续返回错误；
- `200` 回复的数量比所有通知数量少两倍；
- 通知处理时间超过 5 秒钟。

如要再次接收通知，请在卖家个人中心重新确认服务 URL 地址（详见 [1.1 申请流程](#11-申请流程)）。
