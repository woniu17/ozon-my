# 妙手订单数据提取 — 功能设计文档

> **目标**:通过 miaoshou-helper 插件从妙手 ERP 历史订单页批量提取**采购信息、称重重量、本地备注**,经 ERP 后端落库,补全本地 ERP 中 Ozon API 无法获取的字段。
>
> 调研基线:妙手 ERP `erp.91miaoshou.com/order/package/all?appPackageTab=all`(2026-09-01 实测,点击"下一页"抓包分析)

***

## 1. 背景与目标

### 1.1 现状

本地 ERP(`erp-backend-lite`)已通过 Ozon API 同步订单到 `op_ozon_order` / `op_package` 等表,但以下数据**仅存在于妙手 ERP**,Ozon API 不提供:

| 数据   | 妙手来源                           | 本地 ERP 现状                          |
| ---- | ------------------------------ | ---------------------------------- |
| 采购信息 | 用户在妙手手动录入(1688/拼多多单号、卖家、金额、物流) | `op_purchase_order` 表结构就绪,但数据需逐条手填 |
| 称重重量 | 妙手交运时回填                        | `op_package` 无此字段                  |
| 本地备注 | 妙手包裹级 `appNote`                | `op_package.note` 字段就绪但为空          |

### 1.2 目标

通过插件自动调用妙手 ERP 的内部 API,批量提取上述三项数据,经 ERP 后端写入本地数据库,实现**妙手 → 本地 ERP 的数据迁移/回补**。

***

## 2. 妙手 API 结构分析

### 2.1 主订单列表 API

```
POST https://erp.91miaoshou.com/api/order/package/render_list/searchOrderPackageList
Content-Type: application/x-www-form-urlencoded
```

**请求参数**(关键字段):

| 参数               | 说明      | 示例值           |
| ---------------- | ------- | ------------- |
| `page`           | 页码(1 起) | 6             |
| `pageSize`       | 每页条数    | 20            |
| `appPackageTab`  | Tab 筛选  | all           |
| `source`         | 来源页面    | orderHistory  |
| `sortField`      | 排序字段    | gmtOrderStart |
| `sortType`       | 排序方向    | desc          |
| `waitProcessTab` | 处理状态筛选  | all           |

### 2.3 请求头签名

妙手 API 请求头含 `x-app-hippo`(32 位 hex 签名)、`x-timestamp`、`x-front-version` 等自定义头。**content script 在页面同源 context 调用 fetch 时 cookie 自动携带,但自定义签名头需由页面 JS 生成**。

| 妙手 appPackageOperateStatus | ERP operate\_status     |

### 4.2 两种 API 调用策略

妙手 API 请求含 `x-app-hippo` 签名头。实现时**优先尝试方案 A,失败降级方案 B**:

**方案 A:content script 直接 fetch(首选)**

content script 在页面同源 context 调用 `fetch`,cookie 自动携带。若服务端仅校验 session cookie 而不严格校验 `x-app-hippo`,则可直接使用:

```javascript
const resp = await fetch('/api/order/package/render_list/searchOrderPackageList', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams({ page: 1, pageSize: 20, ... }).toString()
});
```

**方案 B:拦截页面 fetch 响应(降级)**

若方案 A 因签名校验失败,则注入 `<script>` 到主世界 hook `window.fetch`,拦截页面自身的 API 响应,同时通过 DOM 点击"下一页"驱动翻页:

```javascript
// 注入主世界脚本,hook fetch 拦截响应
const script = document.createElement('script');
script.text = `
  const _fetch = window.fetch;
  window.fetch = async function(...args) {
    const resp = await _fetch.apply(this, args);
    const url = typeof args[0] === 'string' ? args[0] : args[0]?.url;
    if (url?.includes('searchOrderPackageList')) {
      const data = await resp.clone().json();
      window.postMessage({ source: 'ms-hook', type: 'page-data', data }, '*');
    }
    return resp;
  };
`;
document.documentElement.appendChild(script);
```

#### 5.1.2 新增 `ms-orders-extract.js`

核心职责:

1. 监听 `chrome.runtime.onMessage`,处理 `MS_EXTRACT_ORDERS`
2. 调用妙手 API 翻页提取(方案 A 或 B)
3. 每页提取后合并采购信息
4. 返回完整数据给 background

```javascript
(() => {
  'use strict';
  const MS_LIST_API = '/api/order/package/render_list/searchOrderPackageList';
  const MS_OUTBOUND_API = '/api/order/package/render_list/getOpOrderPackageIdAndOutboundInfoMap';
  const BASE_PARAMS = 'source=orderHistory&appPackageTab=all&sortField=gmtOrderStart&sortType=desc&waitProcessTab=all&supplierProcessStatus=all&isLogisticsCompanyGroupMode=1&priceType=profit';

  // 提取单页:主列表 + 采购信息
  async function fetchPage(page, pageSize = 20) {
    const listBody = new URLSearchParams({ page, pageSize, ...parseParams(BASE_PARAMS) });
    const listResp = await fetch(MS_LIST_API, {
      method: 'POST', credentials: 'include',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: listBody.toString()
    });
    if (!listResp.ok) throw new Error(`MS_HTTP_${listResp.status}`);
    const listData = await listResp.json();
    if (listData.result !== 'success') throw new Error('MS_BAD_RESPONSE');
    const packages = listData.packageList || [];

    // 批量获取采购信息
    const ids = packages.map(p => p.opOrderPackageId);
    if (!ids.length) return { packages: [], outbound: {} };
    const outboundBody = new URLSearchParams();
    ids.forEach((id, i) => outboundBody.append(`opOrderPackageIds[${i}]`, id));
    const obResp = await fetch(MS_OUTBOUND_API, {
      method: 'POST', credentials: 'include',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: outboundBody.toString()
    });
    const obData = await obResp.json();
    const outbound = obData.opOrderPackageIdAndOutboundInfoMap || {};
    return { packages, outbound, totalCount: listData.total || 0 };
  }

  // 全量提取(自动翻页)
  async function extractAll({ onProgress, maxPages = 100 }) {
    const all = [];
    for (let page = 1; page <= maxPages; page++) {
      const { packages, outbound } = await fetchPage(page);
      if (!packages.length) break;
      // 合并采购信息到 package
      for (const pkg of packages) {
        const ob = outbound[pkg.opOrderPackageId];
        if (ob) pkg._outbound = ob;
        all.push(simplify(pkg));
      }
      onProgress?.({ page, count: all.length });
      if (packages.length < 20) break; // 最后一页
      await new Promise(r => setTimeout(r, 800)); // 间隔,避免频率限制
    }
    return all;
  }

  // 精简为 ERP 需要的字段
  function simplify(pkg) {
    const ob = pkg._outbound || {};
    const purchaseOrders = Object.values(ob.purchaseOrders || {});
    return {
      // 包裹匹配键
      postingNumber: pkg.platformPackageId,
      appPackageNo: pkg.appPackageNo,
      shopNick: pkg.shopNick,
      shopId: pkg.shopId,
      // 称重 + 备注
      weighingWeight: pkg.packageWeighingWeight || null,
      note: pkg.appNote || null,
      // 采购信息列表
      purchases: purchaseOrders.map(po => ({
        platform: po.purchasePlatform,
        purchaseSn: po.purchaseOrderSn,
        buyerAccount: po.purchaseOrderBuyer,
        sellerName: po.purchaseOrderSeller,
        paymentAmount: parseFloat(po.purchaseOrderPayment) || 0,
        status: po.purchaseOrderStatus,  // has_send/has_sign
        sendAt: po.purchaseOrderSendTime,
        logisticsCompany: po.purchaseOrderPackages?.[0]?.purchaseOrderLogisticsName || null,
        logisticsNo: po.purchaseOrderPackages?.[0]?.purchaseOrderWaybillCode || null,
        lastTrace: po.purchaseOrderPackages?.[0]?.lastLogisticsTrace || null,
        items: (po.items || []).map(it => ({
          opOrderItemId: it.opOrderItemId,
          purchasePrice: parseFloat(it.purchasePrice) || 0,
          purchaseNum: parseInt(it.purchaseNum) || 1
        }))
      }))
    };
  }

  chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
    if (msg?.type === 'MS_EXTRACT_ORDERS') {
      extractAll({
        onProgress: (p) => chrome.runtime.sendMessage({ type: 'MS_PROGRESS', ...p })
      })
        .then(orders => sendResponse({ ok: true, orders, count: orders.length }))
        .catch(err => sendResponse({ ok: false, error: String(err.message || err) }));
      return true; // async
    }
    if (msg?.type === 'MS_PING') {
      sendResponse({ ok: true, url: location.href });
      return false;
    }
    return false;
  });
})();
```

#### 5.1.3 `background.js` — 新增消息路由

```javascript
// ── 妙手订单提取 ──────────────────────────────────────────
async function fetchMiaoshouOrders({ maxPages = 100 } = {}) {
  const tabs = await chrome.tabs.query({ url: 'https://erp.91miaoshou.com/order/package/all*' });
  let msTab = tabs[0];
  if (!msTab) {
    msTab = await chrome.tabs.create({
      url: 'https://erp.91miaoshou.com/order/package/all?appPackageTab=all',
      active: false
    });
    await new Promise(r => setTimeout(r, 8000)); // 等待页面加载
  }
  return new Promise((resolve) => {
    chrome.tabs.sendMessage(msTab.id, { type: 'MS_EXTRACT_ORDERS', payload: { maxPages } }, (resp) => {
      if (chrome.runtime.lastError) {
        resolve({ ok: false, error: chrome.runtime.lastError.message });
      } else {
        resolve(resp || { ok: false, error: '妙手页面无响应' });
      }
    });
  });
}

// 消息路由新增
chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  // ... 现有 PDD/ALI/TB 处理不变 ...
  if (msg.type === 'MS_GET_ORDERS') {
    fetchMiaoshouOrders(msg.payload || {})
      .then(result => sendResponse(result));
    return true;
  }
  return false;
});
```

#### 5.2.2 `order-daos.js` — 新增批量 upsert 方法

```javascript
/** 从妙手数据批量回补:称重+备注+采购信息 */
function upsertFromMiaoshou(records) {
  return runInTx(() => {
    let updated = 0, created = 0;
    for (const r of records) {
      // 按 posting_number 匹配本地包裹
      const pkg = db.prepare(
        `SELECT id, store_id FROM op_package
         WHERE logistics_no = ? OR package_no = ?`
      ).get(r.postingNumber, r.appPackageNo);

      if (!pkg) { created++; continue; } // 本地无此订单,跳过

      // 更新称重 + 备注(仅非空字段覆盖)
      const sets = [], vals = [];
      if (r.weighingWeight != null) { sets.push('weighing_weight = ?'); vals.push(r.weighingWeight); }
      if (r.note != null) { sets.push('note = ?'); vals.push(r.note); }
      if (sets.length) {
        vals.push(pkg.id);
        db.prepare(`UPDATE op_package SET ${sets.join(', ')}, gmt_modified = ? WHERE id = ?`)
          .run(...vals, nowIso(), pkg.id);
        updated++;
      }

      // 采购信息 upsert
      for (const po of r.purchases || []) {
        upsertPurchaseOrder(pkg, po);
      }
    }
    return { updated, created, total: records.length };
  });
}
```

## 6. 关键设计决策

| 决策点      | 选择                                | 理由                                |
| -------- | --------------------------------- | --------------------------------- |
| API 调用位置 | content script(页面 context)        | 同源 fetch 自动带 cookie,referer 正确    |
| 签名头处理    | 先试无签名,失败降级 hook                   | 避免逆向 x-app-hippo 算法;hook 更稳定但侵入性强 |
| 数据流向     | content→background→ERP 后端         | 复用现有 PDD/1688 桥接架构                |
| 匹配策略     | posting\_number 优先,package\_no 兜底 | Ozon posting\_number 在两系统中一致      |
| 采购信息写入   | 复用 submitPurchase 逻辑              | 保持数据一致性(冲回逻辑/状态联动)                |
| 状态覆盖策略   | 称重/备注覆盖,状态不覆盖                     | 状态机只前进;称重/备注为补充数据可覆盖              |

## 8. 风险与注意事项

- **登录态**:妙手 session 过期时 API 返回 401/403,需提示用户在浏览器中重新登录妙手

- **签名头**:方案 A(无签名)可能失败,需准备方案 B(hook fetch)降级

- **数据量**:943 条/48 页,单次提取约 40 秒(800ms×48),可接受

- **幂等性**:重复提取不会产生重复采购单(`UNIQUE(platform, purchase_sn)` 约束)

- **状态安全**:采购信息 upsert 复用 `submitPurchase` 的冲回逻辑,取消关联时金额正确冲回
