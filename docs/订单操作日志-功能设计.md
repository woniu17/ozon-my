# 订单操作日志 — 功能设计

- 日期: 2026-11-01
- 背景: 安卓端扫描入库出现问题难排查;订单全链路操作分散在多个表/时间戳,无法按订单聚合。
- 目标:
  1. 安卓端扫描入库全链路事件落服务器,方便问题排查。
  2. 订单写操作统一落日志,按订单展示操作时间线(详情页)。

## 数据模型

`op_order_log` 表(见 `erp-backend-lite/src/db/schema.sql`):

| 列 | 说明 |
|---|---|
| package_id | op_package.id |
| posting_number | 货件号(按单排查主键) |
| store_id | 店铺 id |
| action | 英文动作标识(ship / purchase / camera_start ...) |
| action_name | 中文名(入库 / 打单 / ...) |
| result | success / failed / pending / warning / info |
| message | 可读描述 / 失败原因 |
| detail | JSON 详情(截断 2000) |
| source | web / android / system |
| operator / ip | 操作人 / 来源 |
| created_at | UTC ISO(带 Z),客户端按设备时区转北京时间 |

索引: `(package_id, id DESC)`、`(store_id, posting_number, id DESC)`、`(created_at DESC)`。

## 后端

- `src/utils/order-log.js`: `logOrderAction()` 统一写日志,写入失败仅告警不影响主流程。
- 接口:
  - `GET /admin/api/order-process/logs?packageId=&postingNumber=&action=&result=&source=&page=&pageSize=` 查询(时间倒序)。
  - `POST /admin/api/order-process/logs` 写入(主要供安卓上报客户端事件,source=android)。
- 已埋点:`ship`(入库)全部成功/失败/幂等/竞态分支。
- 待扩展(Phase 3):扫描打单、采购、打印、发运、搁置、同步、库存修改等其余写接口。

## 安卓端

- `StockScanFragment`:扫码链路事件异步上报(source=android,失败进内存队列补报,上限 100):
  camera_start/camera_failed/camera_permission_denied、scan_received、
  scan_invalid_format、scan_search_start/scan_not_found/scan_status_skipped/scan_search_failed、
  multi_confirm_show/cancel、ship_submit/ship_success/ship_already/ship_pending/ship_failed、
  manual_input、scan_pause/scan_resume、records_clear。
- `OrderDetailActivity`:新增「操作记录」卡片,`GET logs?packageId=` 时间倒序展示(结果着色)。

## 部署

2. 安卓:重新构建 APK 并部署。
