# 店铺健康页面 - 功能设计

> 覆盖 Web 端 / 安卓端 / H5 端
> 数据源：`POST /v1/rating/index/fbs/info`、`POST /v1/rating/index/fbs/posting/list`（Ozon 错误指数）

---

## 1. 背景与目标

Ozon 错误指数（error index）衡量 FBS/rFBS 卖家的两类过失：

| 错误类型 | 含义 |
|---|---|
| `SELLER_CANCELLATION` | 卖家取消（买家下单后卖家取消） |
| `SELLER_DELAY` | 卖家逾期（未在 cutoff 前完成入库/交付） |

错误指数过高会触发 `WARNING`（警告）→ `CRITICAL`（可能封禁），每次错误还产生处理费用。本功能为三端新增「店铺健康」页面，让运营：

- **一眼看清**当前错误指数与费用水平，判断账号是否处于警告/危险区
- **掌握趋势**：指数/费用按天变化，活动后集中发货是否在恶化
- **定位货件**：下钻到具体影响货件号，反查订单并处理（补发、申诉宽限等）

---

## 2. 数据来源

| Ozon API | 用途 | 落库表 |
|---|---|---|
| `/v1/rating/index/fbs/info` | 周期错误指数 + 按天明细（index / 费用） | `op_rating_daily` |
| `/v1/rating/index/fbs/posting/list` | 影响指数的货件明细（分页） | `op_rating_error_posting` |

采用「**定时落库 + 手动刷新**」模式：页面读本地库秒开，历史可追溯；手动同步调 Ozon 实时拉取，避免每次打开页面都打 Ozon 接口。

## 3. 后端设计

### 3.1 新增表（`schema.sql` + migration 幂等）

```sql
-- 每日错误指数快照（同店铺同日覆盖）
CREATE TABLE IF NOT EXISTS op_rating_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  store_id INTEGER NOT NULL,
  date TEXT NOT NULL,                          -- YYYY-MM-DD
  index_by_date REAL NOT NULL DEFAULT 0,
  processing_costs_sum_by_date REAL NOT NULL DEFAULT 0,
  period_from TEXT,
  period_to TEXT,
  synced_at TEXT,
  UNIQUE(store_id, date)
);
CREATE INDEX IF NOT EXISTS idx_rating_daily_store_date ON op_rating_daily(store_id, date);

-- 影响错误指数的货件（同店铺同货件覆盖）
CREATE TABLE IF NOT EXISTS op_rating_error_posting (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  store_id INTEGER NOT NULL,
  posting_number TEXT NOT NULL,
  posting_error_type TEXT NOT NULL,            -- SELLER_CANCELLATION / SELLER_DELAY
  delivery_schema TEXT,                        -- FBS / rFBS / erFBS
  error_at TEXT,
  index REAL NOT NULL DEFAULT 0,
  has_grace_status INTEGER NOT NULL DEFAULT 0, -- 1=享受宽限（不计费/可申诉）
  charge_percent REAL NOT NULL DEFAULT 0,
  charge_price REAL NOT NULL DEFAULT 0,
  charge_price_currency_code TEXT,
  product_price REAL NOT NULL DEFAULT 0,
  product_price_currency_code TEXT,
  synced_at TEXT,
  UNIQUE(store_id, posting_number)
);
CREATE INDEX IF NOT EXISTS idx_rating_err_store_error ON op_rating_error_posting(store_id, error_at);
```

### 3.2 `ozon-opi.js` 新增函数

```js
// 错误指数汇总（无请求体）
export function ratingIndexFbsInfo(store) {
  return call(store, '/v1/rating/index/fbs/info', {});
}

// 影响错误指数的货件列表（分页）
export function ratingIndexFbsPostingList(
  store,
  { dateFrom, dateTo, cursor, limit = 100, postingNumbers } = {}
) {
  const body = { filter: { date_from: dateFrom, date_to: dateTo }, limit };
  if (cursor) body.cursor = cursor;
  if (postingNumbers?.length) body.filter.posting_numbers = postingNumbers;
  return call(store, '/v1/rating/index/fbs/posting/list', body);
}
```

### 3.3 新增路由（独立 `rating` 模块或挂 order-process 风格）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/api/rating/health/summary?storeIds=&from=&to=` | 汇总：指数、费用、影响货件数、类型分布、每日趋势（读落库表） |
| GET | `/admin/api/rating/health/errors?storeIds=&from=&to=&cursor=&limit=` | 影响货件分页列表（join `op_ozon_order` 返回订单状态便于跳转） |
| POST | `/admin/api/rating/health/sync` | 手动触发同步（body: `{ storeIds?, from?, to? }`），调 Ozon 拉取并 upsert |
| GET | `/admin/api/rating/health/sync-status` | 同步任务进度（供前端轮询） |

### 3.4 定时同步

在 `app.js` 启动流程注册定时任务：**每天 03:00** 自动同步全店铺近 35 天错误指数与货件明细（对齐现有 accrual-by-day 的每 24h 同步模式）。同步为串行 + 节流，避免触发 Ozon 限流。

### 3.5 数据关联

`op_rating_error_posting.posting_number` ↔ `op_ozon_order.posting_number`（唯一键），前端点击货件号可跳转订单详情 / 订单处理搜索，反查订单上下文。

## 4. 页面设计（三端统一信息架构）

### 4.1 顶部筛选区

- 店铺选择（多选，默认全选）
- 时间范围预设：近 7 天 / 近 30 天 / 本月 / 上月 / 自定义（对齐现有统计页交互）
- 「同步」按钮：手动拉取最新数据（完成后自动刷新）

### 4.2 概览指标卡（4 个）

| 指标卡 | 内容 | 状态色 |
|---|---|---|
| 错误指数 | 当前周期指数值（大数字） | 绿（OK）/ 黄（WARNING）/ 红（CRITICAL） |
| 错误处理费用 | 金额 + 币种 | 默认 |
| 影响货件数 | 总数，拆「取消 X / 逾期 Y」 | 红 / 橙 |
| 宽限货件数 | `has_grace_status=true` 数量 | 灰（提示可申诉） |

### 4.3 每日趋势图

- 折线：每日错误指数（`index_by_date`）
- 柱状：每日错误处理费用（`processing_costs_sum_by_date`）
- **实现：纯 CSS/SVG**（三端一致，不引入图表库；Web 无 echarts 依赖，安卓/H5 用自定义 View/view 绘制）

### 4.4 分布统计（小卡片）

- 错误类型分布：卖家取消 vs 卖家逾期（数量 + 费用占比）
- 配送方案分布：FBS / rFBS / erFBS

### 4.5 影响货件明细表

| 列 | 内容 | 交互/样式 |
|---|---|---|
| 货件号 | `posting_number` | 可点击 → 跳订单详情/订单处理搜索 |
| 错误类型 | `SELLER_CANCELLATION` / `SELLER_DELAY` | 红 / 橙标签 |
| 出错日期 | `error_at` | 文本 |
| 货件价值 | `product_price` + 币种 | 右对齐 |
| 处理费用 | `charge_price` + 币种 | 右对齐，红字 |
| 宽限状态 | `has_grace_status` | 有宽限=灰绿「宽限」徽标 / 无宽限=红「计费」徽标 |
