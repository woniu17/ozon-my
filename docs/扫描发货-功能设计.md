# 扫描发货(扫码打单交运) — 功能设计

> 版本:v1.0(2026-09-13,设计定稿待实施)
> 模块:erp-backend-lite 订单处理(order-process)
> 前置:docs/订单打印标签-功能设计.md(面单打印链路,已实施)、docs/采购订单-Ozon订单关联管理-功能设计.md
> 关联决策(2026-09-13 用户确认):
> ① 妙手同步的称重重量 = 发货重量,同一概念同一字段(`op_package.weight`),本系统定位为替代妙手 ERP;
> ② 扫描命中已交运订单 → 提示 + 可选重打(不改状态)。

***

## 1. 背景与目标

当前打单交运在订单处理页逐行操作:切到「待打单发货」Tab → 找到订单 → 点「打印面单」→ 出纸 → 流转交运。打包发货场景下操作员手上拿着包裹,需要:

- 用扫码枪扫**采购快递单号**(也可能手输采购单号/Ozon 单号)直接定位订单;
- 录入**实物称重重量**(发货重量,用于国际配送费公式 `3.37 + 0.0281 × weight_g`);
- **待打单发货**状态下自动打印面单并流转交运;非该状态则明确提示、不打印、不改状态;
- 随时查看今日/昨日发货记录。

**目标**:新增「扫描发货」页面,扫码 → 称重 → 出纸 → 交运一条龙,全程键盘操作(扫码枪 + 数字键盘),替代妙手 ERP 扫描发货页。

***

## 2. 现状调研结论(可复用资产)

| 能力 | 现状 | 复用方式 |
| --- | --- | --- |
| 全局搜索 | `order-daos.js buildPackageWhere` 已支持 `globalKeyword/globalMode`,匹配 7 类字段:Ozon单号(posting_number)/包裹号(package_no)/包裹物流号(logistics_no)/offer_id/SKU/采购单号(purchase_sn)/采购物流单号(po.logistics_no) | 直接复用 `GET /admin/api/order-process/list`,零后端改动 |
| 面单打印 | OrderProcess.vue `onPrintLabel`:拉PDF → 菜鸟组件CNPL静默打印 → `markPrinted` 流转交运;print-agent.js 全套(连接/选打印机/pdfjs转PNG/CNPL模板/超时) | 前端函数级复用 |
| 交运流转 | `order-daos.js markWaybillPrinted`:写 `waybill_printed_at`,wait_ship → ship_success | 复用,不改 |
| 重量体系 | `getWeightsByPackageIds` 优先级:miaoshou_package.weighing_weight > custom_weight_g > Ozon同步 | **需调整**(见 §6.2) |
| 发货时间 | `op_package.waybill_printed_at`(UTC ISO) | 今日/昨日记录查询依据 |

**关键发现(影响搜索默认值)**:拼单提交采购时,采购单号/物流单号以**逗号拼接**入库(`purchaseForm.logisticsNo = tracks.join(',')`),精确匹配会漏单。因此扫描框**默认模糊匹配**(运单号足够长,误命中概率极低),保留精确模式为可选项。

## 3. 总体方案

```
扫码枪输入(Enter) ──► GET /order-process/list 全局搜索(模糊,跨所有状态)

              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
          0 个结果        1 个结果           N 个结果
              │               │                │

                              │                │

                                      │

                    │(服务端权威二次校验状态)
                    ├─ canShip=false ──► 横幅红色「订单状态问题」

                                          │

                    fetchPackageLabel(缓存优先) → pickLabelPrinter → printLabelImage(CNPL静默出纸)

                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼

            刷新发货记录+回焦        在 wait_ship            打印+流转,不再提交重量)
```

选择卡片而非表格的理由:扫码场景需要大操作目标与醒目的重量录入;视觉语言沿用 OrderProcess 的 product-item / purchase-item / tag 体系。

### 4.2 扫描输入区

- 白底卡片容器(`--card` + `--border` + `--radius` + `--shadow`),`position: sticky; top: 0; z-index: 10`,滚动时始终可见。
- **大号输入框**:高 48px、字号 16px、mono 字体(ui-monospace 栈,同 `.store-id`/`.mono`),placeholder=`扫描/输入 采购快递单号 · 采购单号 · Ozon订单号`。加大尺寸的原因:扫码枪回车误触场景下,大目标 + 大字号是主操作的视觉锚点。
- 匹配模式下拉(`.filter-input`):默认「模糊匹配」(防拼单逗号拼接漏单,见 §2),可选「精确匹配」。
- **组件状态指示**:右侧小徽章,菜鸟打印组件 WebSocket 连接状态(绿点=已连接 / 灰点=未连接);进入页面时后台探测一次(getAgentPrinters),失败不阻塞。
- 搜索按钮(`.btn-primary`,与输入框同高)。
- **自动聚焦**:页面加载即 focus;每次发货终态(成功/失败)后回焦并 `select()` 全选(扫码枪连续作业,无需手动清空)。
- Enter 触发搜索(扫码枪自带回车,即插即用)。

### 4.3 结果反馈横幅

三态,内容保留至下一次搜索触发时刷新:

| 态 | 样式 | 内容示例 |
| --- | --- | --- |
| 成功 | `tag-ok` 色系(#d1fae5 底 + #059669 字) | `✓ 已交运 15200000-0001 · 重量 350g · 面单已打印` |
| 失败 | `tag-err` 色系(#fee2e2 底 + #dc2626 字) | `✗ 订单状态问题:订单已取消,不打印面单` |
| 提示 | `tag-info` 色系(#dbeafe 底 + #1d4ed8 字) | `未找到匹配订单` / `命中 3 个包裹,请选择` |

- `role="status"` + `aria-live="polite"`:发货结果自动播报给屏幕阅读器。
- 颜色不作唯一信息载体:图标(✓/✗/!)+ 文字语义并存。
- (可选增强,M4)成功/失败提示音:扫码场景标配,`Audio` 短蜂鸣,可在页面内开关。

卡片纵向堆叠,单卡结构(自上而下):

```
┌─────────────────────────────────────────────────────┐
│ 头部: [15200000-0001](mono大字) [待打单发货](tag) 店铺名 │
│ 产品区: [64px缩略图] 商品标题(2行截断)                  │
│                       Offer ID:xxx · 产品单价:¥xx      │
│                       × 2(数量,>1 高亮)                │

│         采购金额 ¥25 · 上家名 · 顺丰 SF1234567890      │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ 分隔线(dashed)─ ─ ─ ─ ─ ─ ─ ─ ─  │

└─────────────────────────────────────────────────────┘
```

- **选中态**:左侧 3px `--primary` 竖条 + `#eff6ff` 浅蓝底(参照 `.sync-progress-bar` 配色);点击卡片即选中。
- **多结果**:仅选中卡片的重量输入框可用,其余 disabled(防止回车误发错单);单结果自动选中并聚焦重量框。
- **非 wait_ship 卡片**:状态 tag 显示原因(如 `[已取消]` tag-err),操作条整体禁用置灰,卡片保持可读(opacity 不低于 0.6,信息完整可辨)。
- 拆单子件沿用「子件」tag-mute 标识。
- 卡片点击目标整卡可点(`cursor: pointer`),键盘可达(Tab + Enter 选中)。
- **加载态**:搜索中渲染 2-3 张骨架卡(灰条 skeleton,参照 `#f3f4f6`),不用裸 spinner。

### 4.5 重量录入

- **可见 label「重量(g)」**,不用 placeholder 替代(placeholder 只展示参考值)。
- `inputmode="numeric"`、`type="text"` + 前端校验:正整数 1~50000 克;非法值在输入框**下方**显示红色错误文案(`.error-text`),`aria-describedby` 关联,Enter 不触发提交。
- 参考重量提示:placeholder 显示 `参考:350g(订单称重)`(取 weightG/weightSource),**不自动填充**——强制人工读秤,防止旧重量直接提交。
- 输入框宽 ~120px、右对齐、数字用 tabular-nums;Enter = 提交发货。
- 提交按钮「打印并发货」:大号 btn-primary(padding 10px 20px),打印中显示「打印中…」并禁用。

### 4.6 发货记录(右侧栏)

- 标题行 + Tab(「今日(N)」/「昨日(M)」)+ 刷新按钮。
- Tab 样式沿用 OrderProcess `.tab-btn` + `.tab-count`(计数角标),不新造胶囊。
- 数据源:`GET /scan-ship/records?day=today|yesterday`,按 `waybill_printed_at` **北京时间**日界(00:00)切分,倒序,AppPager 分页(20/页)。
- 行内容:`HH:mm` + Ozon单号(mono,点击跳订单处理页全局搜索,复用 MiaoshouOrders「本地包裹」跳转模式 `router.push({path:'/order-process', query:{kw}})`) + 商品缩略图 + 标题截断 + 重量。
- 空状态:「今日暂无发货记录」居中灰字(`.empty`)。
- 发货成功后自动刷新当前 Tab 计数与列表。

### 4.9 键盘操作流(扫码枪适配)

```
[扫描框] Enter ──► 搜索
   ├─ 0 结果: 横幅提示 → 回焦扫描框
   ├─ 1 结果: 自动选中卡片 → focus 重量框
   └─ N 结果: 点击/Tab+Enter 选中卡片 → focus 重量框
[重量框] Enter ──► 提交发货(打印 → 流转 → 终态)
   └─ 终态: 自动回焦扫描框并全选(连续扫码零鼠标)
[Esc] 任意时刻: 清空当前结果回初始态(扫描框聚焦)
```

- 主路径全程键盘:扫码(Enter)→ 输重(Enter)→ 自动回焦。多结果选卡是唯一需要鼠标/方向键的分支(拼单场景,低频可接受)。
- 焦点环统一走 global.css 的 `:focus-visible` 模式(`box-shadow: 0 0 0 3px rgba(37,99,235,0.35)`),不额外发明。

### 4.10 可访问性要点

- 横幅 `role="status" aria-live="polite"`,发货结果自动播报。
- 重量错误文案 `aria-describedby` 关联输入框。
- 状态不只靠颜色:tag 文字(「待打单发货」「已取消」)+ 图标承载语义。
- 骨架卡加载、`prefers-reduced-motion` 沿用全局规则。
- 扫码输入框 `aria-label="扫描输入"`(视觉 placeholder 不作无障碍名)。

## 5. 交互逻辑设计

### 5.1 主流程时序

```
操作员           前端(ScanShip.vue)                后端                    菜鸟组件/打印机
 │ 扫码+Enter │──GET /list(globalKeyword)──►│
 │            │◄──packages[0..N]──────────│
 │ 输重量+Enter│──POST /scan-ship/submit──►│
 │            │   {packageId, weightG}     │─UPDATE weight(仅wait_ship)
 │            │◄──{canShip, status}───────│
 │            │   canShip=false → 横幅红,终态│
 │            │──POST /package-label──────►│─缓存命中?Ozon拉取
 │            │◄──PDF(blob)──────────────│
 │            │──printLabelImage(PNG)─────────────────────────►│ 出纸
 │            │◄──printed────────────────────────────────────│
 │            │──POST /print-label───────►│─markWaybillPrinted
 │            │   (wait_ship→ship_success) │
 │ 看横幅确认  │ 横幅绿 + 刷新记录 + 回焦扫描框 │
```

**为什么发货主流程不加确认弹窗**:出纸即物理确认(面单在手上),弹窗会打断扫码节奏;误发防护由「状态权威校验 + 重量强制人工输入」承担。唯一保留确认框的场景是已交运重打(§5.4)。

### 5.2 订单状态判定矩阵

判定依据 `operate_status`(+ `is_ignored`),**两道防线**:卡片渲染时用搜索快照预显示;submit 时服务端按 DB 当前值权威二次校验(覆盖搜索后状态被同步任务/他端操作改变的场景)。

| operate_status | 卡片预显示 | submit 结果 | 处理 |
| --- | --- | --- | --- |
| wait_ship(待打单发货) | tag-info「待打单发货」 | canShip=true | 打印面单 + 流转交运 |
| wait_process | tag-mute「待处理(未采购)」 | canShip=false | 横幅:请先提交采购信息 |
| ship_success | tag-ok「已交运」 | canShip=false | 横幅 + 重打确认框(§5.4) |
| wait_receiver_confirm | tag-mute「已发货」 | canShip=false | 横幅:已发货(已交运) |
| cancelled | tag-err「已取消」 | canShip=false | 横幅:订单已取消 |
| 已搁置(is_ignored=1) | tag-mute「已搁置」 | canShip=false | 横幅:已搁置 |

### 5.3 打印失败与重试

| 场景 | 表现 | 恢复路径 |
| --- | --- | --- |
| 409 LABEL_NOT_READY(Ozon装配后45-60s才出单) | 横幅「面单尚未就绪,稍后重试」 | 卡片按钮变「重试打印」;重量已保存,重试只走打印+流转,不再提交重量 |
| 409 LABEL_NOT_AVAILABLE(Ozon拒绝,状态已变) | 横幅「仅待发货状态可打印,建议先同步订单状态」 | 引导去订单处理页点「同步」 |
| 菜鸟组件未启动/连接失败 | 横幅红色提示启动组件 | **不自动回退浏览器打印框**(弹窗打断扫码节奏);点「重试打印」;订单处理页仍保留 iframe 兜底路径 |
| 出纸超时/打印失败 | 横幅红色 + 具体原因 | 同「重试打印」路径 |
| submit 网络失败 | 横幅红色 | 重量未落库,直接重按 Enter 重试整个流程 |

**重试打印的语义**:`重量已保存` 状态下,重试仅执行 fetchPackageLabel → printLabelImage → markPrinted,幂等安全(面单走文件缓存,markPrinted 对 wait_ship 幂等)。

### 5.4 已交运订单重打(已确认决策)

扫描命中 `ship_success`:
1. 横幅提示「订单状态问题:已交运」;
2. 弹确认框(useConfirmStore):`面单丢失或打花?重新打印面单(不改状态)`;
3. 确认 → fetchPackageLabel(缓存秒出)→ 静默打印 → 横幅「面单已重新打印(交运订单,状态不变)」;
4. 取消/关闭 → 终态回焦。

与订单处理页「交运订单重打」语义完全一致,面单走 `data/waybills/` 文件缓存。

### 5.5 拼单多结果处理

扫同一采购单号/物流单号命中 N 张卡片(1采购单→N包裹拼单):
- 全部渲染,wait_ship 卡可操作,其余置灰;
- 逐个选中 → 输重 → 发货;每发一单,该卡片变「已交运」终态(不消失,留作上下文),右侧记录+1;
- 已发完的卡片提供「重打」入口(同 §5.4 语义)。

### 5.6 并发与防重

- `printingPkgId` 互斥:打印期间该卡片按钮禁用;扫描框允许继续输入搜索(查看下一单),但发货提交需等打印完成(与 OrderProcess `printingId` 模式一致)。
- 双击防护:提交按钮在请求全程 disabled。
- 服务端 `markWaybillPrinted` 本身幂等(CASE WHEN 保护),重复提交不产生脏状态。

## 6. 后端设计

### 6.1 新增 API(挂 order-process.js 现有 router,复用鉴权)

**① `POST /admin/api/order-process/scan-ship/submit`**

```jsonc
// req
{ "packageId": 123, "weightG": 350 }   // weightG: 正整数克, 1~50000
// res(HTTP 200)
{ "ok": true, "data": { "canShip": true,  "operateStatus": "wait_ship" } }
{ "ok": true, "data": { "canShip": false, "operateStatus": "cancelled", "message": "订单已取消" } }
// 404 包裹不存在 / 400 weightG 非法
```

逻辑:校验参数 → 读当前 `operate_status` 权威判定 → **仅 wait_ship 时** `UPDATE op_package SET weight = ?, gmt_modified = ?` → 返回 canShip + message。非 wait_ship 不写重量(避免污染已取消单数据)。

**② `GET /admin/api/order-process/scan-ship/records?day=today|yesterday&page=1&pageSize=20`**

- SQL:`WHERE waybill_printed_at >= ? AND waybill_printed_at < ?`(北京时间日界换算 UTC 区间)ORDER BY `waybill_printed_at DESC`;
- 响应复用 /list 聚合结构:items / purchaseLinks / weightG+weightSource / waybillPrintedAt / postingNumber / storeName / packageNo,前端零转换。

### 6.2 数据模型与重量语义(已确认决策落地)

**不新增列。`op_package.weight` 即「发货重量」唯一载体**(妙手同步与扫描发货写同一字段,同一概念):

| 写入方 | 行为 |
| --- | --- |
| 扫描发货 submit | `UPDATE op_package SET weight = ?`(仅 wait_ship) |
| 妙手同步 syncMsToLocal | **加保护**:仅当 `waybill_printed_at IS NULL`(未交运)或 weight 为空时更新——发货重量一经交运即锁定,妙手不可能比本系统实物秤更准 |

**`getWeightsByPackageIds` 优先级调整**(order-daos.js):

```
1. op_package.weight                      → 发货重量(扫描录入/妙手同步),weightLabel「重量(称)」
2. miaoshou_package.weighing_weight       → 兜底(ms-to-local 未同步过但妙手表有称重)
3. product_data_cache.custom_weight_g     → 系统维护
4. Ozon 后台同步重量
```

收益:零 migration、概念归一;发货后国际配送(估)公式立即用真实秤重,OrderProcess/妙手订单页金额列自动受益。

### 6.3 不改动清单

- 全局搜索 DAO(buildPackageWhere)
- `markWaybillPrinted`(交运流转)
- 面单拉取/文件缓存/HMAC短链(package-label 系)
- 菜鸟打印组件协议(print-agent.js)
- 前端 request/order-process API 封装(仅追加两个函数)
