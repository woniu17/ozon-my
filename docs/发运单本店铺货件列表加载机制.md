# 发运单本店铺货件列表加载机制

> 适用范围：ERP 后端 `erp-backend-lite` + Web 前端（`CarriageManage.vue`）
> 最后更新：2026-11-09（补发写入 Ozon `set-postings`、候选双来源找回）

## 1. 概述

发运单（Carriage）相关页面涉及多个"本店铺货件列表"的加载场景：详情货件列表、添加货件候选、创建发运待发运货件、补发货件。各场景数据源不同：

- **详情列表** 以 Ozon 当前发运单真实货件列表为准（保证与 Ozon 后台一致），经本地归属过滤后展示；
- **添加候选** 只展示"跨发运单补发候选"，双来源（Ozon 当前列表 + 本地历史找回）；
- **创建发运** 使用 Ozon 未妥投列表（可发运货件池）；
- **补发** 必须真正调用 Ozon `set-postings` 写入发运单，同时落本地表。

## 2. 核心数据源

### 2.1 Ozon 接口

| 接口 | 封装函数 | 用途 | 加载场景 |
|---|---|---|---|
| `POST /v1/assembly/carriage/posting/list` | `carriagePostingList` | 某个发运单的**真实货件列表** | 详情列表、添加候选、补发时读取 |
| `POST /v4/posting/fbs/unfulfilled/list` | `postingFbsUnfulfilledList` | 未妥投货件列表（可发运货件池） | 创建发运弹窗·待发运货件 |
| `POST /v1/carriage/set-postings` | `carriageSetPostings` | 全量覆盖发运单货件组成 | **补发时真正写入 Ozon** |
| `POST /v2/carriage/delivery/list` | `carriageDeliveryList` | 发运单清单（仅汇总，无货件明细） | 发运清单页面，不用于货件列表 |

> 注意：`/v2/carriage/delivery/list` 只返回 `carriages[].postings_count` 等汇总字段，**不含货件明细**，不能作为货件列表数据源。`/v1/posting/carriage-available/list` 已废弃（2026-03-20 关闭）。

### 2.2 本地表 `op_carriage_posting`（货件↔发运单关系）

- `UNIQUE(store_id, carriage_id, posting_number)`，`removed_at` 软删除（保留历史轨迹）
- `source`：`'ozon'`（Ozon 同步本店行）/ `'manual'`（跨店混装、本地补记行，不受 Ozon 列表同步影响）
- 归属保持：同一货件默认只属于一个发运单（`source='ozon'` 活跃行）；补发（`forceReship`）后可同时在多个发运单
- 冗余 `ozon_order_id` / `package_id`：用于 JOIN 本地订单/包裹做富化

### 2.3 本地富化（不调 Ozon）

商品图、`shipment_date`、订单状态、`operate_status`、`waybill_printed_at` 等均从本地 `op_ozon_order` / `op_package` / `product_data_cache` 补全（`hydrateLocalPostings` / `attachPostingProductImages` / `attachPostingShipmentDates` / `attachLocalPostingProducts`）。

## 3. 加载场景与链路

### 3.1 发运单详情货件列表（`POST /admin/api/order-process/carriage/posting-list`）

```
Ozon carriagePostingList（当前发运单真实货件，如 10 个）
  → 本地富化（商品图、shipment_date）
  → resolvePostingsForCarriage 归属过滤（见 §4.1）
  → attachInOtherCarriageMarks（展示行打"已发货·在 #xxx"补发标记）
  → syncCarriagePostings 用【Ozon 原始列表】刷新本地关联（补发行不被误删）
  → 合并跨店 manual 行（buildManualPostingObjects）
  → 快照写回 op_carriage_history.postings_json
```

- 展示源始终是 Ozon 当前发运单列表，保证与 Ozon 后台一致；
- 归属过滤只影响"展示"，不影响本地生命周期——本地刷新必须用 Ozon 原始列表（含被过滤的跨单货件），否则补发行会被 `markAbsentPostingsRemoved` 误删。

### 3.2 添加货件弹窗 · 本店货件 tab（`POST /admin/api/order-process/carriage/available-postings`）

```
Ozon carriagePostingList（同一发运单列表）
  → syncCarriagePostings 刷新本地关联
  → resolvePostingsForCarriage 归属过滤
  → 候选 = 双来源合并去重：
      来源1：Ozon 列表中归属过滤排除的跨单货件
      来源2：buildReshipCandidatesFromLocal（本地历史找回，见 §4.3）
  → 本地富化 + 打 inOtherCarriage 标记
  → 返回 existingCarriagePostings（该货件在其他发运单的活跃行）
```

- 候选只展示"需要补发的跨单货件"，不混入与本发运单无关的跨单候选；
- 勾选后走 `reship`（§3.4），真正写入 Ozon。

### 3.3 创建发运弹窗 · 待发运货件（`POST /admin/api/order-process/carriage/pending-postings`）

```
Ozon postingFbsUnfulfilledList（未妥投列表）
  → 过滤 status=awaiting_deliver + deliveryMethodId
  → 本地富化商品图/shipment_date
  → attachInOtherCarriageMarks（已发货在其他发运单的标记）
  → 返回 existingCarriagePostings
```

- 与创建发运同一数据源，反映"该配送方式下所有已准备发运货件"。

### 3.4 补发货件（`POST /admin/api/order-process/carriage/posting/reship`）

```
校验货件在本店其他发运单活跃（否则 400）
  → 拉取当前发运单完整货件列表（carriagePostingList，分页）
  → 目标货件不在列表时：
      追加后调用 Ozon /v1/carriage/set-postings 全量覆盖（真正写入 Ozon）
      检查返回 result，Ozon 拒绝则报错
  → upsertCarriagePostingRow(forceReship) 写本地活跃行
  → 返回 { carriageId, postingNumber, fromCarriageId, ozonAdded }
```

- **补发必须调用 Ozon `set-postings`**，否则只写本地会导致 Ozon 后台和详情列表都不显示；
- Ozon 实测支持同一货件同时在多个发运单（如 `0164795750-0006-1` 同时存在于 125676118 与 125810729）。

### 3.5 跨店货件 tab（`POST /admin/api/order-process/carriage/mixed-candidates`）

完全本地库，`source='manual'`，与以上链路独立（大包混装）。

## 4. 归属过滤与补发闭环

### 4.1 归属过滤 `resolvePostingsForCarriage`

核心 SQL：货件在本店其他发运单有活跃 `ozon` 行、且**当前发运单无活跃记录** → 从当前发运单展示中排除，返回 `crossCarriagePostings`；已补发（当前发运单有活跃行）→ 不再排除。

> 易错点：SQL 中 `IN (...)` 位于 `NOT EXISTS` 之前，参数数组顺序必须是 `[storeId, carriageId, ...numbers, carriageId]`（numbers 先于 `me.carriage_id`），否则归属检查会绑定到错误的发运单。

### 4.2 补发标记与提示

- 详情列表行内：`已发货·在 #{{ otherCarriageId }}`（红色标签）
- 详情列表顶部：黄色提示条（`crossCarriagePostings` 非空时显示"当前发运单不展示，如需补发请在添加货件中勾选"）
- 创建发运/待发运弹窗：同样打标记，不弹窗打扰

### 4.3 补发候选找回 `buildReshipCandidatesFromLocal`

从 `op_carriage_posting` 中查找"曾在当前发运单关联过（存在历史行）、现仍在本店其他发运单活跃"的 ozon 货件。用于 Ozon 侧把货件移出当前发运单列表后，候选仍能找回补发入口；限定历史关联避免展示无关跨单候选。

### 4.4 补发写入 Ozon

`reship` 接口在写本地前，先读取当前发运单完整货件列表，目标货件不在时追加并调用 `carriageSetPostings` 全量覆盖。Ozon 返回 `result: false` 时抛出明确错误。

## 5. 关键设计意图

- **详情列表 = Ozon 当前发运单真实货件**（经归属过滤），保证与 Ozon 后台一致；
- **添加候选 = 跨单补发候选**（Ozon 列表来源 + 本地历史找回双保险），只展示需要确认归属的货件；
- **补发 = Ozon 写入 + 本地记录双落库**，`set-postings` 全量覆盖是唯一写入通道；
- **本地表是"关系/状态"层**：记录归属、补发、跨店混装、已随大包发出状态，用于过滤判断、候选找回、历史快照。
