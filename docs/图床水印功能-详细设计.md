## 1. 模块详细设计

### 1.1 image-host.js（图片托管核心模块）

**文件路径**：`erp-backend-lite/src/services/image-host.js`

**职责**：封装"下载原图 → sharp 渲染水印 → 落盘 → 返回公网 URL"完整流程，提供幂等性保证。

#### 1.1.1 模块级常量与初始化

```js
import { request } from 'undici';
import { createHash } from 'node:crypto';
import { existsSync, mkdirSync, writeFileSync } from 'node:fs';
import { join, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';
import logger from '../middleware/log.js';
import config from '../config/index.js';

const __dirname = dirname(fileURLToPath(import.meta.url));
const PUBLIC_DIR = join(__dirname, '../public');
const IMAGES_DIR = join(PUBLIC_DIR, 'images');

// sharp 可选导入(缺失时模块整体降级,调用方需检测 sharpAvailable)
let sharp = null;
try {
  const mod = await import('sharp');
  sharp = mod.default || mod;
} catch {
  sharp = null;
}
export const sharpAvailable = !!sharp;
```

**设计要点**：
- 使用顶层 `await import('sharp')` 实现 sharp 的可选加载
- 导出 `sharpAvailable` 布尔值，供调用方前置检查
- `PUBLIC_DIR` / `IMAGES_DIR` 基于当前模块路径计算，与 `app.js` 挂载 `express.static` 的目录一致

#### 1.1.2 processImage 函数（核心导出）

**签名**：
```js
async function processImage(url, sku, templateConfig) -> string
```

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `url` | string | 是 | 原图 URL（http/https） |
| `sku` | string | 是 | SKU 标识，用于子目录命名（会 sanitize） |
| `templateConfig` | object | 是 | 水印模板配置 JSON，必须含 `type` 字段 |

**返回值**：`string` — 公网可访问的图片 URL

**异常**：任一步失败时抛 `Error`，由调用方（`watermark.js`）捕获并降级为透传原 URL。

**流程伪代码**：
```
1. 校验 config.imageHostBaseUrl 非空,否则抛 'IMAGE_HOST_BASE_URL 未配置'
2. 校验 sharp 可用,否则抛 'sharp 未安装'
3. 校验 templateConfig.type ∈ {text, border, image},否则抛 '水印模板 type 无效'
4. hash = md5(url)
5. safeSku = sanitizeSku(sku)
6. subDir = IMAGES_DIR/safeSku
7. filePath = subDir/hash.jpg
8. publicUrl = {imageHostBaseUrl}/images/{safeSku}/{hash}.jpg
9. 幂等检查: if existsSync(filePath) return publicUrl
10. mkdirSync(subDir, {recursive: true})
11. 下载原图:
    res = request(url, {method:'GET', headersTimeout:30000, bodyTimeout:30000})
    if res.statusCode >= 400: throw '下载原图失败: HTTP {statusCode}'
    buffer = Buffer.from(await res.body.arrayBuffer())
12. 渲染水印:
    renderedBuffer = await renderWatermark(buffer, templateConfig)
13. 落盘:
    writeFileSync(filePath, renderedBuffer)
14. return publicUrl
```

**关键设计**：
- **幂等性**：基于 `{sku}/{md5(url)}.jpg` 文件名，文件已存在时直接返回 URL，跳过下载和渲染
- **超时控制**：`headersTimeout` 和 `bodyTimeout` 均为 30 秒
- **错误分层**：下载失败和渲染失败分别记录 warn 日志后 re-throw，便于排查

#### 1.1.3 renderWatermark 函数（分发器）

**签名**：
```js
async function renderWatermark(buffer, config) -> Buffer
```

**职责**：按 `config.type` 分发到三种渲染器。

| `config.type` | 调用函数 | 说明 |
|---------------|----------|------|
| `'text'` | `renderText(buffer, config.text)` | 文字水印 |
| `'border'` | `renderBorder(buffer, config.border)` | 边框水印 |
| `'image'` | `renderImage(buffer, config.image)` | 图片水印 |
| 其他 | 抛 `Error('未知水印类型: ' + config.type)` | — |

#### 1.1.4 renderText 函数（文字水印）

**签名**：
```js
async function renderText(buffer, textCfg) -> Buffer
```

**`textCfg` 字段**：

| 字段 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| `content` | string | — | 是 | 文字内容 |
| `fontSize` | number | `32` | 否 | 字号 |
| `color` | string | `'#FFFFFF'` | 否 | 字体颜色（hex 格式） |
| `opacity` | number | `0.6` | 否 | 透明度（0–1） |
| `position` | string | `'bottom-right'` | 否 | 位置枚举 |

**实现原理**：
1. 加载原图 `sharp(buffer).metadata()` 获取宽高 `W` / `H`
2. 根据 `position` 计算文字坐标 `{x, y}` 和 `text-anchor`（通过 `computeTextPosition`）
3. 构造 SVG 字符串（尺寸与原图一致）：
   ```svg
   <svg width="${W}" height="${H}">
     <text x="${x}" y="${y}" font-size="${fontSize}" fill="${color}"
           fill-opacity="${opacity}" font-family="sans-serif"
           text-anchor="${anchor}">${escapeXml(content)}</text>
   </svg>
   ```
4. 用 `sharp(buffer).composite([{input: Buffer.from(svg), gravity: 'centre'}]).jpeg().toBuffer()` 合成

**坐标计算规则**（`computeTextPosition`，padding=20）：

| position | x | y | anchor |
|----------|---|---|--------|
| `top-left` | `20` | `20 + fontSize` | `start` |
| `top-right` | `W - 20` | `20 + fontSize` | `end` |
| `bottom-left` | `20` | `H - 20` | `start` |
| `bottom-right` | `W - 20` | `H - 20` | `end` |
| `center` | `W / 2` | `(H + fontSize) / 2` | `middle` |

#### 1.1.5 renderBorder 函数（边框水印）

**签名**：
```js
async function renderBorder(buffer, borderCfg) -> Buffer
```

**`borderCfg` 字段**：

| 字段 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| `width` | number | `10` | 否 | 边框宽度（像素） |
| `color` | string | `'#000000'` | 否 | 边框颜色（hex） |
| `opacity` | number | `0.5` | 否 | 透明度（0–1） |

**实现原理**：
1. `hexToRgb(color)` 解析 hex 颜色为 `{r, g, b}`
2. 用 sharp `extend` 扩展四周：
   ```js
   sharp(buffer).extend({
     top: width, bottom: width, left: width, right: width,
     background: { r, g, b, alpha: opacity }
   }).jpeg().toBuffer()
   ```

#### 1.1.6 renderImage 函数（图片水印）

**签名**：
```js
async function renderImage(buffer, imageCfg) -> Buffer
```

**`imageCfg` 字段**：

| 字段 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| `url` | string | — | 是 | 水印图片 URL |
| `scale` | number | `0.2` | 否 | 水印图相对原图宽度的比例 |
| `opacity` | number | `0.5` | 否 | 透明度（0–1） |
| `position` | string | `'bottom-right'` | 否 | 位置枚举 |

**实现原理**：
1. 下载水印图（undici request，30s 超时）
2. 获取原图尺寸 `meta = sharp(buffer).metadata()`
3. 计算水印图目标宽度：`wmWidth = Math.round(meta.width * scale)`
4. 缩放水印图并调整透明度：
   ```js
   sharp(wmBuffer).resize(wmWidth).ensureAlpha(opacity).toBuffer()
   ```
5. `position` → sharp `gravity` 常量映射（`positionToGravity`）：

| position | gravity |
|----------|---------|
| `top-left` | `northwest` |
| `top-right` | `northeast` |
| `bottom-left` | `southwest` |
| `bottom-right` | `southeast` |
| `center` | `centre` |

6. 合成：`sharp(buffer).composite([{input: wmResized, gravity}]).jpeg().toBuffer()`

#### 1.1.7 辅助函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `computeTextPosition(position, W, H, fontSize)` | → `{x, y, anchor}` | 计算文字水印坐标 |
| `positionToGravity(position)` | → string | position 字符串转 sharp gravity 常量 |
| `escapeXml(s)` | → string | 转义 `& < > " '` |
| `sanitizeSku(sku)` | → string | 把 SKU 中非 `[a-zA-Z0-9_-]` 字符替换为 `_` |
| `hexToRgb(hex)` | → `{r, g, b}` | hex 颜色转 RGB（支持 `#FFF` 和 `#FFFFFF`） |

### 1.2 watermark.js（水印加工入口）

**文件路径**：`erp-backend-lite/src/services/enrichments/watermark.js`

**职责**：作为 `prepareBundleItems` 加工链的一个步骤，负责查模板、遍历图片、调用 `image-host.processImage`、失败降级。

#### 1.2.1 apply 函数

**签名**：
```js
async function apply(items, message) -> Array
```

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `items` | Array | 商品 items 数组，每个 item 含 `offer_id` / `images[]` |
| `message` | object | followSell 消息体，含 `watermarkTemplateId` / `applyWatermark` |

**返回值**：处理后的 items 数组（图片 URL 已替换为图床 URL，失败图透传原 URL）

**完整流程**：

```
步骤 1: 前置检查 sharpAvailable
  if (!sharpAvailable):
    logger.warn('sharp 未安装,水印降级为透传')
    return items  // 整批透传

步骤 2: 解析 message.watermarkTemplateId
  templateId = Number(message?.watermarkTemplateId) || 0
  if (!templateId):
    logger.warn('watermarkTemplateId 为空,水印透传')
    return items  // 整批透传

步骤 3: 查 watermark_templates 表拿 config
  try:
    row = db.prepare('SELECT config FROM watermark_templates WHERE id=?').get(templateId)
    if (!row):
      logger.warn({templateId}, '水印模板不存在,水印透传')
      return items  // 整批透传
    templateConfig = typeof row.config === 'string' ? JSON.parse(row.config) : row.config
  catch e:
    logger.warn({templateId, err}, '水印模板读取失败,水印透传')
    return items  // 整批透传

  if (!templateConfig || !templateConfig.type):
    logger.warn({templateId}, '水印模板 config 无效(type 缺失),水印透传')
    return items  // 整批透传

步骤 4: 遍历 items 处理图片
  total = 0, processed = 0, fallback = 0

  for item in items:
    if (!Array.isArray(item.images)) continue
    sku = String(item.offer_id || '').split('-')[0] || 'unknown'

    for img in item.images:
      // 只处理 http(s) URL
      if (!img?.file_name || !/^https?:\/\//i.test(img.file_name)) continue
      total++
      try:
        publicUrl = await processImage(img.file_name, sku, templateConfig)
        img.file_name = publicUrl  // 成功:替换 URL,保留 default 不变
        processed++
      catch e:
        logger.warn({offerId, url, err}, '水印处理失败,透传原图')
        fallback++
        // 失败:img.file_name 保持原值(透传)

  logger.info({totalItems, total, processed, fallback}, '水印处理完成')
  return items
```

**关键设计**：
1. **SKU 提取**：`item.offer_id` 形如 `"4143566763-0718-qx"`，取首段作为子目录名（与 `listing-builder.js` 的 offer_id 格式一致）
2. **只处理 http(s) URL**：跳过已是图床 URL 的 `/images/...` 相对路径或 `data:` URL
3. **保留 `img.default` 字段不变**：确保 `transformItemForPortal` 仍能正确识别主图
4. **单图失败不影响其他图**：try-catch 在图片循环内
5. **统计日志**：`{totalItems, total, processed, fallback}` 四个维度

### 1.3 listing-builder.js（上架消息构造）

**文件路径**：`erp-backend-lite/src/services/listing-builder.js`

**职责**：在两个函数中注入 `applyWatermark` / `watermarkTemplateId` 到 message 对象。

#### 1.3.1 buildListingMessage 函数注入逻辑

**位置**：函数末尾 `return` 语句之前（约第 281-302 行）

**逻辑**：
```js
// 水印字段注入(供 prepareBundleItems 加工链读取)
// 优先 options 显式传入,否则按 templateId 读模板配置
let applyWatermark = options.applyWatermark ?? null;
let watermarkTemplateId = options.watermarkTemplateId ?? null;
if (templateId && (applyWatermark === null || watermarkTemplateId === null)) {
  const tplCfg = getTemplateConfig(templateId);
  if (tplCfg) {
    if (applyWatermark === null) applyWatermark = tplCfg.applyWatermark === true;
    if (watermarkTemplateId === null) watermarkTemplateId = tplCfg.watermarkTemplateId ?? null;
  }
}

return {
  message: {
    items: [item],
    defaultStock,
    templateId,
    applyWatermark: applyWatermark === true,        // 严格布尔化
    watermarkTemplateId: watermarkTemplateId ?? null,
  },
  offerId,
};
```

**优先级**：
1. `options.applyWatermark` / `options.watermarkTemplateId`（显式传入优先）
2. `getTemplateConfig(templateId)` 读取的模板配置
3. 默认值 `false` / `null`

#### 1.3.2 executeListing 函数兜底注入

**位置**：`upsertTaskItems(...)` 之后、`prepareBundleItems(...)` 调用之前（约第 343-356 行）

**逻辑**：
```js
// 水印字段注入(与 buildListingMessage 对齐):
// 若 message 未显式传入 applyWatermark / watermarkTemplateId,则按 templateId 读模板配置补齐
// 确保 Preview.vue → /ozon/products/import → executeListing 路径下水印加工链能正常触发
const tplId = Number(message.templateId) || 0;
if (tplId && (message.applyWatermark === undefined || message.watermarkTemplateId === undefined)) {
  const tplCfg = getTemplateConfig(tplId);
  if (tplCfg) {
    if (message.applyWatermark === undefined) message.applyWatermark = tplCfg.applyWatermark === true;
    if (message.watermarkTemplateId === undefined) message.watermarkTemplateId = tplCfg.watermarkTemplateId ?? null;
  }
}
// 兜底:确保两个字段有默认值,避免 prepare-bundle.js 门控判定 undefined
if (message.applyWatermark === undefined) message.applyWatermark = false;
if (message.watermarkTemplateId === undefined) message.watermarkTemplateId = null;
```

**设计要点**：
- `executeListing` 是 `Preview.vue → /ozon/products/import` 的入口，前端未传水印字段时由这里兜底
- 使用 `undefined` 判断（而非 `null`）区分"未传"和"显式传 null"
- 兜底确保 `prepare-bundle.js` 门控 `message.applyWatermark === true` 不会因 `undefined` 误判

### 1.4 prepare-bundle.js（加工链门控）

**文件路径**：`erp-backend-lite/src/services/prepare-bundle.js`

**职责**：调整 watermark 步骤的门控条件。

#### 1.4.1 门控变更

**变更前**（约第 388 行）：
```js
if (flags.watermark && message.applyWatermark !== false) {
  logger.info('加工链: 水印...');
  processed = await applyWatermark(processed, message);
}
```

**变更后**：
```js
if (message.applyWatermark === true) {
  logger.info('加工链: 水印...');
  processed = await applyWatermark(processed, message);
}
```

**变更理由**：
- 原门控依赖 `flags.watermark`（来自 `feature-flags.json`），全局关闭时即便模板 `applyWatermark=true` 也不渲染
- 新门控改为由 `listing_templates.applyWatermark` 显式开启，解除对 `feature-flags.watermark` 的依赖
- 其他加工步骤（`ai_rewrite` / `ai_poster` / `copy_ban_solution`）门控保持不变

#### 1.4.2 顶部注释更新

```js
// 可插拔加工链:
//   - ai_rewrite / ai_poster / copy_ban_solution: 由 feature-flags 门控
//   - watermark: 由 listing_templates.applyWatermark 显式开启(不依赖 feature-flags.watermark)
//   ai_rewrite → watermark → ai_poster → copy_ban_solution
```

### 2.3 watermark_templates.config JSON Schema

```typescript
interface WatermarkTemplateConfig {
  type: 'text' | 'border' | 'image';

  // type='text' 时必填
  text?: {
    content: string;                // 必填
    fontSize?: number;              // 默认 32
    color?: string;                 // 默认 '#FFFFFF'(hex 格式)

  };

  // type='border' 时必填
  border?: {
    width?: number;                 // 默认 10(像素)
    color?: string;                 // 默认 '#000000'(hex 格式)
    opacity?: number;               // 默认 0.5(范围 0-1)
  };

  // type='image' 时必填
  image?: {
    url: string;                    // 必填(水印图 URL)
    scale?: number;                 // 默认 0.2(相对原图宽度比例)
    opacity?: number;               // 默认 0.5(范围 0-1)
    position?: Position;            // 默认 'bottom-right'
  };
}

type Position = 'top-left' | 'top-right' | 'bottom-left' | 'bottom-right' | 'center';
```

## 4. 错误处理与降级矩阵

### 4.1 整批降级场景

| 场景 | 检测点 | 行为 | 日志 |
|------|--------|------|------|
| sharp 未安装 | `watermark.js` 步骤 1 | `return items`（透传） | `warn: 'sharp 未安装,水印降级为透传'` |
| `watermarkTemplateId` 为空 | `watermark.js` 步骤 2 | `return items`（透传） | `warn: 'watermarkTemplateId 为空,水印透传'` |
| 模板不存在 | `watermark.js` 步骤 3 | `return items`（透传） | `warn: {templateId}, '水印模板不存在,水印透传'` |
| 模板 config JSON 解析失败 | `watermark.js` 步骤 3 | `return items`（透传） | `warn: {templateId, err}, '水印模板读取失败,水印透传'` |
| 模板 config 无效（type 缺失） | `watermark.js` 步骤 3 | `return items`（透传） | `warn: {templateId}, '水印模板 config 无效(type 缺失),水印透传'` |
| `IMAGE_HOST_BASE_URL` 未配置 | `image-host.js` `processImage` | 抛错 → 单图透传 | `warn: {err, url, sku}, '...未配置'`（由 watermark.js catch 记录） |
| 加工链整体异常 | `prepare-bundle.js` catch | `processed = items`（透传未加工 items） | `error: {err}, '加工链异常,降级为透传'` |

### 4.2 单图降级场景

| 场景 | 检测点 | 行为 | 日志 |
|------|--------|------|------|
| `IMAGE_HOST_BASE_URL` 未配置 | `image-host.js` | 抛错 → 该图透传 | `warn` |
| sharp 未安装（运行时丢失） | `image-host.js` | 抛错 → 该图透传 | `warn` |
| 模板 type 无效 | `image-host.js` | 抛错 → 该图透传 | `warn` |
| 下载原图网络错误 | `image-host.js` | 抛错 → 该图透传 | `warn: {err, url, sku}, '下载原图失败'` |
| 下载原图 HTTP 4xx/5xx | `image-host.js` | 抛错 → 该图透传 | `warn` |
| 下载原图超时（30s） | `image-host.js` | 抛错 → 该图透传 | `warn` |
| sharp 渲染失败 | `image-host.js` | 抛错 → 该图透传 | `warn: {err, url, sku}, '渲染水印失败'` |
| 落盘失败 | `image-host.js` | 抛错 → 该图透传 | `warn`（由 watermark.js catch） |

### 4.3 错误传播路径

```
image-host.processImage 抛错
    │
    ▼
watermark.apply 的 for 循环内 try-catch 捕获
    │
    ▼
logger.warn({offerId, url, err}, '水印处理失败,透传原图')
    │
    ▼
fallback++
    │
    ▼
继续处理下一张图(img.file_name 保持原值)
```

## 5. 幂等性设计

### 5.1 幂等机制

**文件名规则**：`{sku}/{md5(url)}.jpg`

- `sku`：经过 `sanitizeSku` 处理（非 `[a-zA-Z0-9_-]` 字符替换为 `_`）
- `md5(url)`：对原图 URL 取 MD5 哈希

**幂等检查**：
```js
if (existsSync(filePath)) {
  return publicUrl;  // 跳过下载和渲染
}
```

### 5.2 幂等场景验证

| 场景 | 行为 |
|------|------|
| 同一 SKU 重复触发上架 | 文件已存在，直接返回 URL，不重复下载/渲染 |
| 不同 SKU 引用同一图片 URL | 分别落盘到各自 SKU 子目录（不共享） |
| 原图 URL 变化（如 CDN 切换） | MD5 不同，视为新图片重新处理 |

### 5.3 并发安全

- 当前实现无文件锁，理论上存在并发写入同一文件的竞态
- 实际场景下同一 SKU 不会并发上架（`batch-upload-poller` 串行处理批次内 item）
- 如未来需要并发上架，可加 `fs.writeFileSync` 的原子写入（先写临时文件再 rename）

## 9. 性能与资源

### 9.1 性能特征

| 指标 | 估值 | 说明 |
|------|------|------|
| 单图处理耗时 | 1–3 秒 | 取决于原图大小和网络延迟 |
| 单批次处理方式 | 串行 | 当前无并发控制，图片逐张处理 |
| sharp 内存占用 | 约 2–5 倍原图大小 | sharp 内部解码 + 渲染 |

### 9.2 磁盘空间

- 单张图片处理后大小：约 50–200 KB（JPG 压缩）
- 假设每日处理 1000 个 SKU，每个 SKU 5 张图：约 100–500 MB/天
- 建议定期清理或挂载独立磁盘

### 9.3 网络带宽

- 下载原图：从源站拉取，消耗出口带宽
- OPI 拉取图片：从 ERP 后端公网反代拉取，消耗入口带宽
- 建议监控带宽使用情况
