# 价格管理 — 概要设计

> 2026-09-18 · erp-backend-lite
>
> 目标:在订单处理右侧新增「价格管理」导航页,维护本系统采购价与商品重量,
> 结合 Ozon 实时售价计算利润率,按目标成本利润率反推新价格并一键更新到 Ozon。

---

## 1. 背景与目标

### 1.1 现状

- 商品重量已可维护(`product_data_cache.custom_weight_g`,商品列表页手动设置,SKU 关联)
- 采购价没有商品维度的"本系统维护值",只有订单维度的实际采购金额(采购单落库)
- 利润计算逻辑集中在 `order-process.js computeProfit`(预估口径:佣金 16% + 国际配送公式),只在订单处理页使用,商品维度看不到"这个 SKU 赚不赚钱"

### 1.2 目标

1. **商品维度的成本/利润视图**:每个在售商品一眼看到 售价→利润→利润率
2. **本系统维护两个基准值**:采购价(CNY)、重量(g),作为定价与预估的基础
3. **目标利润率定价**:选 10%~50% 目标成本利润率 → 自动算出建议价 → 确认后调 Ozon API 改价
4. **历史订单参考**:展开商品看该 SKU 的历史订单(最新排序),参考实际采购价快捷回填
5. **按利润率排序**:快速找出"卖得亏"的商品

---

## 2. 核心公式(与订单处理预估口径完全一致)

全部以 **CNY** 为单位(实测 `op_ozon_order.order_amount` 存 CNY,与配送公式/采购金额同币种):

```
配送费   delivery = 3.37 + 0.0281 × weight_g
佣金     commission = price × 16%
回款     escrow = price × (1 − 16%) − delivery
利润     profit = escrow − purchase_price
销售利润率 = profit / price
成本利润率 = profit / purchase_price
```

**目标定价反推**(给定目标成本利润率 r):

```
price = (purchase_price × (1 + r) + delivery) / (1 − 16%)
```

例:采购 ¥20,重量 200g(delivery ¥8.99),目标成本利润率 40%:
price = (20 × 1.4 + 8.99) / 0.84 = **¥51.18**

**前置条件**:采购价、重量均未维护时,目标定价列禁用并提示补齐。

**重量取值优先级**(复用现有 `getWeightsByPackageIds` 同款语义,单件化):
`custom_weight_g` > `product_attributes_cache.attributes_data.weight` > 采集表 `weight_g`。

**币种**:实测 v5 价格接口返回 CNY,与订单金额/配送/采购同币种,**全链路无汇率换算**(见 §8)。

## 3. 数据模型

### 3.1 本系统维护值(加列,与 custom_weight_g 同表同键)

```sql
ALTER TABLE product_data_cache ADD COLUMN custom_purchase_price REAL;    -- 本系统采购价(CNY)
ALTER TABLE product_data_cache ADD COLUMN custom_purchase_price_at TEXT; -- 设置时间
```

商品重量沿用现有 `custom_weight_g`,不重复建设。

### 3.2 Ozon 价格缓存表(同步落库,页面读缓存不实时打 Ozon)

> 实测(2026-09-18,YQL01 店):`/v5/product/info/prices` 返回 **currency_code: "CNY"**,
> price/old_price/min_price 全为 CNY,与本地利润公式币种一致,**无需汇率换算**。
> SKU 在 Ozon 全局唯一(不同店铺不会出现同 SKU),故本表以 sku 单列主键。

```sql
CREATE TABLE IF NOT EXISTS op_product_price_cache (
  sku              TEXT PRIMARY KEY,   -- Ozon SKU(全局唯一,用户确认)
  store_id         TEXT NOT NULL,
  product_id       INTEGER,            -- 改价 API 用 product_id(稳定标识)
  offer_id         TEXT,               -- 仅存档参考,不作关联键(可被修改,用户确认)
  price            REAL,               -- 现售价(CNY)
  old_price        REAL,               -- 划线价(CNY)
  min_price        REAL,               -- 促销最低价(CNY)
  currency_code    TEXT,               -- 'CNY'
  sales_percent_fbs REAL,              -- v5 commissions 实际 FBS 佣金率(%,参考展示)
  market_min_price_rub REAL,           -- v5 price_indexes 市场最低价(RUB,参考展示)
  price_index_color  TEXT,             -- 'RED'/'GREEN'...(价格竞争力指示)
  name             TEXT,               -- v3 同步回来的商品名(冗余,列表直显)
  image            TEXT,               -- v3 首图(列表直显)
  raw_json         TEXT,               -- v5 原始 item
  synced_at        TEXT                -- 本次同步时间
);
```

### 3.3 价格变更日志(审计+限频依据)

```sql
CREATE TABLE IF NOT EXISTS op_price_change_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  store_id    TEXT NOT NULL,
  sku         TEXT NOT NULL,
  product_id  INTEGER,
  old_price   REAL, new_price REAL, old_old_price REAL, currency_code TEXT,
  target_rate REAL,              -- 目标成本利润率(%),手动改价为 NULL
  source      TEXT,              -- 'target' 目标定价 | 'manual' 手动
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_price_change_sku ON op_price_change_log(sku, created_at);
```

### 3.4 关联键(实测确认,2026-09-18)

- **SKU 是唯一关联键**:Ozon SKU 全局唯一、不可变;`product_data_cache.sku`、
  `op_ozon_order_item.sku`、`op_product_price_cache.sku` 三者同为 Ozon 数字 SKU,直接 join
- **offer_id 不可作键**(用户确认:同一 SKU 的 offer_id 可修改)——仅存档参考
- **product_id 用于改价**:`/v1/product/import/prices` 传 product_id(稳定标识)
- **v5 无 SKU 字段**,同步时需两步建立映射(实测通过):
  1. `/v5/product/info/prices`(product_id + 价格,CNY)
  2. `/v3/product/info/list` 按 product_id 批量反查(已有封装 `productInfoListV3`,1000/批)
     → `sources[].sku` + name + images → 按 sku 落缓存

## 4. 页面设计(PriceManage.vue)

### 4.1 导航入口

- `App.vue` nav 数组「订单处理」右侧新增 `{ key: '/price-manage', label: '价格管理' }`
- 路由 `/price-manage` → `views/PriceManage.vue`

### 4.2 布局(自上而下)

```
┌─────────────────────────────────────────────────────────────────┐
│ 工具栏: [店铺tabs] [同步Ozon价格] 汇率0.085 · 最近同步 10:32     │
│ 统计条: 商品 156 | 已设采购价 89 | 已设重量 102 | 低于20%成本率 23 │
├─────────────────────────────────────────────────────────────────┤
│ 筛选: [关键词(SKU/名称)] [采购价:全部/已设/未设] [重量:...]      │
│       [利润率区间: __%~__%]  排序: [成本利润率↑ 销量↓ 售价 利润] │
├─────────────────────────────────────────────────────────────────┤
│ 商品 | 售价 | 90天销量 | 采购价* | 参考采购价 | 重量* | 配送费    │
│      | 预估利润 | 销售利润率 | 成本利润率 | 目标定价 | 操作       │

├─────────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────────┘
```

### 4.3 关键交互

1. **行内编辑采购价/重量**:点击单元格直接改,失焦保存(PUT 接口),保存后本行利润率即时重算
2. **参考采购价**:近 90 天该 SKU 实际采购金额/数量的加权均价(从订单+采购关联算),未设采购价时灰字展示 + 「采用」快捷按钮
3. **目标定价**:
   - 下拉选择 10% / 20% / 30% / 40% / 50% / 自定义
   - 选中即在本行显示建议价(如 `¥51.18 → 606₽`,含汇率换算展示)
   - 点「更新价格」→ 确认弹窗(旧价→新价,变化幅度,目标率)→ 调 Ozon 改价 API → toast → 刷新该行
4. **展开订单列表**:点击商品行展开,加载该 SKU 历史订单(倒序),每行带「以此单回填」按钮(采购均价 = 该单采购总额/数量 → 回填采购价输入框待确认)
5. **排序**:成本利润率升序为默认(最亏的排最前);支持 销量/售价/利润/销售利润率
6. **颜色规范**:利润正绿负红,与订单处理页一致

### 4.4 批量操作(一期可选,默认关闭)

- 勾选多行 → 统一设置目标利润率 → 批量改价(串行限速,逐条确认结果)
- 全量"一键目标定价"风险高,**一期不做**,二期评估

## 5. 后端设计(modules/price-manage.js + services)

### 5.1 API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/admin/api/price-manage/prices/sync` | 按 storeId 拉全量:v5 prices(游标)→ v3 反查 sku → 落缓存表;仅手动触发,返回条数 |
| GET | `/admin/api/price-manage/list` | 分页列表:join 价格缓存+商品表+订单聚合(90天销量/参考采购价);支持筛选/排序参数 |
| PUT | `/admin/api/price-manage/sku/:sku` | 设置采购价/重量(写 product_data_cache 两个自定义列) |
| GET | `/admin/api/price-manage/sku/:sku/orders` | 该 SKU 历史订单(倒序,含实际采购金额/实际利润) |
| POST | `/admin/api/price-manage/price-update` | 单品改价:校验→调 Ozon API→写日志→回读校验 |
| GET | `/admin/api/price-manage/summary` | 顶部统计条数据 |

### 5.2 ozon-opi.js 新增封装

```js
// POST /v5/product/info/prices — 游标循环拉全量(实测 limit 1000 可用,total 2214 ≈ 3 页)
productInfoPricesV5(store, { cursor, filter, limit })
// POST /v1/product/import/prices — 更新价格(传 product_id,currency_code='CNY')
productImportPrices(store, prices)
```

`productInfoListV3`(v3 反查 sku)已有封装,直接复用。

### 5.3 改价安全策略(2026-09-18 用户确认)

1. **改价参数**(用户确认):
   - `price` = 建议价
   - `old_price` = price × 2(划线价自动双倍)
   - `min_price` = price(促销最低价兜底)
   - `currency_code` = 'CNY'(实测结算币种)
2. **限频**:Ozon 限制每商品每小时改价 ≤10 次;按日志表统计,超频直接拒绝并提示剩余时间
3. **确认**:前端确认弹窗展示 旧价→新价→变化%;服务端再校验新价与建议价偏差(防前端算错)
4. **回读**:改价接口返回 `updated:true` 后,延迟 30s 用 v5 回读该商品价格校验真正生效(价格生效是异步的,参考备货轮询的经验)
5. **单品改价**:一期仅单品,不做批量(用户确认)
6. **日志**:每次改价落 `op_price_change_log`,页面可查改价历史(二期:商品展开区加"改价记录"子 tab)

### 5.4 利润公式共享

把 `computeProfit` 的预估分支抽为共享 util(如 `services/profit-estimator.js`):

```js
estimateProductProfit({ priceCny, purchaseCny, weightG }) →
  { delivery, commission, escrow, profit, profitRateSale, profitRateCost }
suggestPrice({ purchaseCny, weightG, targetRate }) → priceCny
```

订单处理页与价格管理页共用,**避免两处口径漂移**(教训:利润口径必须单点维护)。

## 6. 数据流

```
[Ozon /v5 prices] --手动点"同步价格"--> (product_id+价格,CNY)
[Ozon /v3 info/list] <--按product_id批量反查-- 同一流程内
                         → sku+名称+图片 → op_product_price_cache(以sku为主键)
[商品表] custom_purchase_price + custom_weight_g <-- 页面维护(订单回填快捷入口)
[订单库] op_package/op_ozon_order_item/op_purchase_link --聚合--> 90天销量/参考采购价/历史订单
                ↓ 全部在服务端 join 计算(全 CNY,无汇率)
          列表行: 售价+采购价+重量 → 预估利润/利润率 → 目标建议价
                ↓ 用户确认(旧价→新价,old_price=新价×2,min_price=新价)
[Ozon /v1 import prices] <-- 改价(限频/日志/30s回读) --> op_price_change_log
```

## 7. 实施拆分(建议顺序)

1. **P1 数据层**:三张表/加列 + DAO(price cache upsert、change log、SKU 订单聚合查询)
2. **P2 公式层**:profit-estimator 抽取 + 订单处理页切换引用(回归验证订单页数字不变)
3. **P3 同步**:ozon-opi 封装 v5 prices + sync 接口 + 定时(可选,默认手动同步)
4. **P4 页面**:PriceManage.vue 列表/编辑/展开订单/排序筛选
5. **P5 改价**:import/prices 封装 + 限频 + 确认 + 日志 + 回读
6. **P6 打磨**:统计条、参考采购价采用、批量改价(可选)

## 8. 决策点(已全部确认,2026-09-18)

| # | 问题 | 结论 |
|---|------|------|
| 1 | v5 prices 返回币种 | **实测 CNY**(YQL01 店),与本地公式同币种,无汇率换算 |
| 2 | import/prices 的 currency_code | **'CNY'**(实测结算币种);改价同时设 old_price=price×2、min_price=price |
| 3 | 关联键 | **SKU 全局唯一**(用户确认);offer_id 可变不作键;v5→SKU 经 v3/product/info/list 映射(实测通过);改价 API 传 product_id |
| 4 | 划线价策略 | old_price = 新价 × 2,min_price = 新价(用户确认) |
| 5 | 价格同步时机 | **仅手动按钮**(用户确认),不做定时/进页自动 |
| 6 | 批量改价 | **一期仅单品**(用户确认),批量/全量目标定价二期评估 |
| 7 | 佣金口径 | 默认 16% 与订单页一致;v5 返回的 commissions.sales_percent_fbs(实测 19%)落缓存,列表作参考列展示,二期可选按实际佣金率精确计算 |

## 9. 风险与边界

- **Ozon 改价生效异步**:与备货状态变更同理,不能信同步返回,需回读校验
- **预估 vs 实际**:本页利润是预估口径(16% 佣金+公式配送),真实利润以订单应计为准;页面利润列标注"估",并在展开订单里展示实际利润供对照
- **采购价 ≠ 实际采购**:本系统采购价是定价基准值,不回写订单实际采购金额;两者差异通过"参考采购价"透明化
- **商品量大**:v5 prices 每页 1000,游标全量;列表分页 20/页,服务端 join 计算避免前端全量
