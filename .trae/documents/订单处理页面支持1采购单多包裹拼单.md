# 订单处理页面支持 1采购单→N包裹(拼单)

## Context

当前订单处理页面 [submitPurchase](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/order-daos.js#L633) 每次都 `INSERT INTO op_purchase_order` 新建采购单,且 `op_purchase_order` 有 `UNIQUE(platform, purchase_sn)`,导致同一采购单号提交第二次会报约束冲突。用户无法把一个已存在采购单关联到第二个包裹(拼单场景)。

但 [op\_purchase\_link 表结构](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/schema.sql#L1001-1011) 本身已支持多对多(`UNIQUE(purchase_order_id, package_id, ozon_order_item_id)` 允许同一采购单关联不同包裹),[unlinkPurchase](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/order-daos.js#L721) 也已支持拼单取消(只删当前 package 的 link,无剩余关联才 unlinked),前端取消关联按钮也已存在([OrderProcess.vue:1614-1618](file:///c:/root/code/ozon-my/erp-backend-lite/web/src/views/OrderProcess.vue#L1614-1618))。

唯一缺口:submitPurchase 不复用已存在采购单 + 提交前无提示。本次改造补齐这两点,实现真正的 1采购单→N包裹。

## 改造点

### 1. 后端:submitPurchase 采购单 INSERT 改 upsert(复用)

文件:[order-daos.js](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/order-daos.js) L655-680

把 `INSERT INTO op_purchase_order (...) VALUES (...)` 改成:

```sql
INSERT INTO op_purchase_order (purchase_sn, platform, purchase_channel, buyer_account, seller_name,
  payment_amount, goods_amount, status, pay_at, send_at, logistics_company, logistics_no, note, gmt_create, gmt_modified)
VALUES (?, ?, 'manual', ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
ON CONFLICT(platform, purchase_sn) DO UPDATE SET
  buyer_account = COALESCE(excluded.buyer_account, op_purchase_order.buyer_account),
  seller_name = COALESCE(excluded.seller_name, op_purchase_order.seller_name),
  payment_amount = CASE WHEN excluded.payment_amount > 0 THEN excluded.payment_amount ELSE op_purchase_order.payment_amount END,
  goods_amount = CASE WHEN excluded.goods_amount > 0 THEN excluded.goods_amount ELSE op_purchase_order.goods_amount END,
  status = excluded.status,
  send_at = COALESCE(excluded.send_at, op_purchase_order.send_at),
  logistics_company = COALESCE(excluded.logistics_company, op_purchase_order.logistics_company),
  logistics_no = COALESCE(excluded.logistics_no, op_purchase_order.logistics_no),
  note = COALESCE(excluded.note, op_purchase_order.note),
  gmt_modified = excluded.gmt_modified
RETURNING id
```

- 用 `RETURNING id` 取真实采购单 id(兼容 INSERT 新建 + ON CONFLICT 复用两条路径,参照 [miaoshou-dao.js:146](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/miaoshou-dao.js#L146) 的 RETURNING 用法)

- `purchase_channel` 不在 UPDATE 列表里,保留原值(模式A platform\_order 不被覆盖成 manual)

- `payment_amount/goods_amount` 用 CASE 保护:新值>0 才覆盖,避免拼单第二次提交时误清零

- 边界:platform='other' + purchaseSn=null 时 SQLite NULL 不参与 UNIQUE,每次新建(符合手工单无唯一单号预期)

### 2. 后端:op\_purchase\_link 保持 INSERT OR IGNORE(不改)

[order-daos.js:687](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/order-daos.js#L687) 的 `INSERT OR IGNORE INTO op_purchase_link` 不动。拼单场景下不同 package\_id 不触发 UNIQUE,正常插入。同一包裹同一采购单重复提交会被 OR IGNORE 跳过(原有行为,本次不引入新 bug)。

### 3. 后端:新增 lookup 路由(提交前提示用)

文件:[order-daos.js](file:///c:/root/code/ozon-my/erp-backend-lite/src/db/dao/sqlite/order-daos.js) 新增函数:

```js
/** 按采购单号查询已关联包裹(拼单提示用) */
function lookupPurchase(platform, purchaseSn) {
  const po = db.prepare(
    `SELECT id, purchase_sn, platform, payment_amount, status FROM op_purchase_order WHERE platform=? AND purchase_sn=?`
  ).get(platform, purchaseSn);
  if (!po) return { exists: false };
  const links = db.prepare(
    `SELECT pl.package_id, p.package_no, o.posting_number,
            SUM(pl.allocated_amount) AS allocated_amount
     FROM op_purchase_link pl
     JOIN op_package p ON p.id = pl.package_id
     JOIN op_ozon_order o ON o.id = p.ozon_order_id
     WHERE pl.purchase_order_id = ?
     GROUP BY pl.package_id ORDER BY pl.package_id`
  ).all(po.id);
  return { exists: true, purchaseOrderId: po.id, paymentAmount: po.payment_amount, linkedPackages: links };
}
```

export 到 orderPackageDao。

文件:[order-process.js](file:///c:/root/code/ozon-my/erp-backend-lite/src/modules/order-process.js) 新增路由(放在 /purchase 路由前):

```js
router.get('/admin/api/order-process/purchase/lookup', (req, res, next) => {
  try {
    const { platform, purchaseSn } = req.query;
    if (!platform || !purchaseSn) return res.status(400).json({ ok: false, message: 'platform/purchaseSn 必填' });
    res.json(ok(orderPackageDao.lookupPurchase(platform, purchaseSn)));
  } catch (e) { next(e); }
});
```

路由头部注释补 `GET /admin/api/order-process/purchase/lookup 查询采购单已关联包裹(拼单提示)`。

### 5. 前端:提交前 lookup + 确认框

文件:[OrderProcess.vue](file:///c:/root/code/ozon-my/erp-backend-lite/web/src/views/OrderProcess.vue) onSubmitPurchase 函数(L448-482)。

在现有校验通过后、`purchaseSaving.value = true` 前,插入拼单检测:

- 仅当 `purchaseForm.platform !== 'other'` 且 `purchaseSn` 非空时调用 lookup

- 若 `lookup.exists && linkedPackages.length > 0`,弹确认框(复用现有 `confirmStore.ask`):

  ```
  采购单 {purchaseSn} 已关联 {N} 个包裹(分摊合计 {sum}元):
  - {packageNo} ({posting_number}) 分摊 {allocatedAmount}元
  ...
  本次将追加关联到当前包裹 {packageNo},请确认下方分摊金额无误。
  ```

- 用户取消则 return,不提交;确认则继续走原 submitPurchase 流程

- import 补 `lookupPurchase`(L11 附近)

## 验证

1. **后端单测**:重启 `pm2 restart erp`,curl 调用 lookup 确认空/非空返回
2. **拼单正向**:包裹A提交采购单X(总额16.66,分摊9.14)→ 包裹B提交采购单X(分摊7.52)→ 两个包裹 total\_purchase\_amount 分别为 9.14 / 7.52,op\_purchase\_order.payment\_amount=16.66(不被覆盖)
3. **lookup 提示**:包裹B提交时填入采购单X单号,弹确认框展示已关联包裹A
4. **取消关联**:包裹B取消关联 → 冲回 7.52,包裹A的 9.14 不变,采购单仍有1个关联不置 unlinked
5. **手工单边界**:platform='other' + purchaseSn 空,多次提交不触发复用,每次新建(符合预期)
6. **前端构建**:`cd web && npm run build`,刷新 `?ts=Date.now()` 强制加载,验证拼单提示弹窗
